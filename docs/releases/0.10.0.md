# HAL CAM 0.10.0

CLI에 `probe`·`cts cases`·`cts run`이 생겨 PC에서 Probe 사양 표와 CTS 원문 메서드까지 돌릴 수 있고, CTS 원문 클래스가 `StillCaptureTest`·`BurstCaptureTest`까지 세 개(40개 메서드)로 늘었습니다. 기기에 검사 대상이 없어 카메라를 열지 않은 원문 메서드는 PASS가 아니라 SKIP으로 표시되고, 어떤 CameraCharacteristics 키의 어떤 값 때문에 빠졌는지가 이유로 붙습니다. 커스텀 케이스 다섯 종은 그대로 있습니다.

## 설치

첨부된 `HAL-Camera-0.10.0.apk`를 설치하세요. 기존 정식 앱과 같은 인증서로 서명했으므로 기존 앱 위에 업데이트할 수 있습니다. 실행 기록과 baseline을 유지하려면 앱을 삭제하지 말고 위에 설치하세요.

| 항목 | 값 |
| --- | --- |
| 패키지 | `dev.halcamera` |
| 버전 | `0.10.0` · versionCode `14` |
| 지원 Android | Android 8.0 이상 · minSdk 26 / targetSdk 36. CTS 원문 케이스는 Android 14(API 34) 이상 |
| 빌드 | 서명된 Release · debuggable=false |
| 인증서 SHA-256 | `f2432413635645cc35e674e498e88ff518abb878065c21f17bb3c2128487b5c1` |

파일 해시는 첨부된 `SHA256SUMS.txt`에서 확인합니다. PC CLI는 `halcam` 0.2.0으로 올라갔습니다(`probe`, `cts cases`, `cts run` 추가). 첨부된 wheel을 `python -m pip install halcam-0.2.0-py3-none-any.whl`로 설치하거나 저장소의 `tools/halcam`을 설치하세요. Python 3.11 이상이 필요하며, Python이 없는 PC에서 `adb`만으로 같은 명령을 부르는 절차는 [CLI 가이드](https://ttolsun.github.io/hal-camera/cli.html)에 있습니다.

## 변경 사항

- CLI 가이드(#106): 개발자 가이드 사이트에 `CLI` 탭이 생겼습니다. 스위치 켜기, `halcam` 설치, 명령 표, Python 없이 `adb`로 provider를 부르는 PowerShell 절차, 아직 CLI에 없는 기능 표를 담습니다.
- CLI 명령 추가(#107): `probe --output DIR`은 화면 없이 모든 카메라의 사양 표를 Probe 화면과 같은 JSON·TXT로 받습니다. `cts cases`는 체크리스트 항목과 키를 돌려주고, `cts run --case KEY …`는 고른 항목을 순서대로 실행해 보고서 JSON(`cts_suite/1`)과 공유 텍스트를 받습니다. CLI가 만든 파일은 요청별 폴더에 두고 기록 만료와 함께 지웁니다.
- CTS 원문 클래스 추가(#108, #112): 같은 AOSP `android16-release` 커밋에서 `StillCaptureTest`(21개)·`BurstCaptureTest`(3개)를 가져왔습니다. `RecordingTest`의 업스트림 본문이 `// TODO. Need implement.`뿐인 세 메서드(`testCameraRecorderOrdering`·`testMediaCodecRecording`·`testTimelapseRecording`)는 목록에서 뺐습니다. 마이크 권한은 `RecordingTest` 항목이 있을 때만 묻습니다.
- CTS SKIP 판정(#112, #113): 가져온 `Camera2SurfaceViewTestCase.openDevice`가 연 카메라를 기록해, JUnit이 통과했어도 카메라를 하나도 열지 않은 메서드는 SKIP입니다. `건너뛴 이유` 카드에 assumption 메시지, 테스트 자신의 "… skipping" 로그(앱 프로세스 logcat에서 읽음), 그리고 `SkipDiagnosis`가 업스트림 `continue` 조건을 다시 읽어 적는 키·값이 순서대로 붙습니다. 예: `모든 카메라: CONTROL_AVAILABLE_SCENE_MODES에 HIGH_SPEED_VIDEO 없음(있는 모드: FACE_PRIORITY, HDR)`. CLI 보고서 JSON의 `detail`에도 같은 문구가 들어갑니다.
- 화면 이름 표기(#104, #105): 버튼과 문서의 화면 이름을 `Live`·`Probe`·`Results`·`Compare`처럼 첫 글자만 대문자로 적습니다. 약어(`CTS`, `API`)는 그대로입니다.
- 문서 도구(#109, #111, #114): `tools/docgen`이 공용 엔진 `@ttolsun/omm-doc-workflow`(0.5.2)를 npm으로 설치해 쓰는 얇은 진입점이 되었습니다. `npm ci --prefix tools/docgen --ignore-scripts` 뒤 `node tools/docgen/docflow.mjs check`로 검사합니다.

## 검증과 해석 범위

0.10.0 버전에서 Debug 단위 테스트, 모든 모듈의 `lintDebug`, `halcam` 단위 테스트, Release 빌드를 확인했습니다. APK의 버전·패키지와 기존 정식 인증서 일치를 검사했습니다.

기기 검증은 모두 Galaxy S25+ SM-S936N / Android 16의 release 서명 로컬 빌드입니다. CTS 원문 40개 메서드를 `halcam cts run`으로 모두 실행해 PASS 33 · FAIL 1 · SKIP 6이었습니다. FAIL은 `StillCaptureTest#testAeCompensation` 하나이며 HAL 판정입니다(카메라 0이 `SENSOR_INFO_EXPOSURE_TIME_RANGE` 상한 213.3 ms를 넘는 288.8 ms를 보고, 카메라 2가 +2 EV 보정을 무시). SKIP 6개는 HEIC·HEIC UltraHDR·DEPTH_JPEG 출력 형식, 정지 영상 bokeh, 고속 동영상 모드, 10비트 AV1 인코더가 이 기기에 없기 때문이며, `testBasic10BitRecordingAV1`은 업스트림 `getDynamicRangeProfile()`이 AV1을 매핑하지 않아 어떤 기기에서도 카메라를 열지 않습니다. `UiAutomation`·`@TestApi` 때문에 setUp에서 죽는 메서드는 없었습니다. `probe`·`cts cases`·`cts run`·취소·부분 보고서 회수는 같은 기기에서 확인했습니다. 실행 중 폰 화면을 조작하면 suite가 중단되므로 긴 실행 동안 폰을 건드리지 마세요.

앱 안의 CTS 결과는 참고용이며 공식 판정은 cts-tradefed의 `test_result.xml`뿐입니다. Python 3.14(uv 관리)와 Windows에서 `halcam` 0.2.0을 실행했고 Linux·macOS는 단위 테스트 CI 범위입니다.

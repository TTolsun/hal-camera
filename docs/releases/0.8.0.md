# HAL CAM 0.8.0

CTS `RecordingTest#testBasicRecording`을 앱 안에서 실행해 카메라·프로파일별 PASS/FAIL을 바로 확인하고, PROBE 필터의 예시와 뒤로가기 동작을 다듬었습니다.

## 설치

첨부된 `HAL-Camera-0.8.0.apk`를 설치하세요. 기존 정식 앱과 같은 인증서로 서명했으므로 기존 앱 위에 업데이트할 수 있습니다. 실행 기록과 baseline을 유지합니다.

| 항목 | 값 |
| --- | --- |
| 패키지 | `dev.halcamera` |
| 버전 | `0.8.0` · versionCode `11` |
| 지원 Android | Android 8.0 이상 · minSdk 26 / targetSdk 36 |
| 빌드 | 서명된 Release · debuggable=false |
| 인증서 SHA-256 | `f2432413635645cc35e674e498e88ff518abb878065c21f17bb3c2128487b5c1` |

파일 해시는 첨부된 `SHA256SUMS.txt`에서 확인합니다. PC CLI는 변경 없이 0.1.0을 사용하며 [0.6.0 릴리스의 wheel](https://github.com/TTolsun/hal-camera/releases/tag/v0.6.0)을 설치할 수 있습니다.

## 변경 사항

- LIVE의 Benchmark 패널에 **CTS 케이스 실행** 버튼이 생깁니다. 카메라마다 CamcorderProfile을 CTS 순서(`HIGH, 2160P, 1080P, 720P, 480P, CIF, QCIF, QVGA, LOW`)로 3초씩 MediaRecorder로 녹화하고, CTS `validateRecording`과 같은 조건(파일·비디오 트랙·크기 일치, 길이 ±20 %, 프레임 드롭률 5 % 미만)으로 프로파일마다 PASS/FAIL/SKIP과 근거를 표시합니다. 결과는 텍스트로 복사·공유할 수 있습니다.
- CTS와 달리 assertion 하나에서 멈추지 않고 프로파일마다 판정하고 계속 진행합니다. 공식 판정은 cts-tradefed의 `test_result.xml`이며, 화면에도 그렇게 표시합니다. 마이크 권한(`RECORD_AUDIO`)이 필요하고 소리를 함께 녹음합니다.
- PROBE 필터의 예시를 `JPEG, 1080, ✗`처럼 모든 Camera2 기기에서 일치하는 값으로 바꿨습니다. `1080`은 `1920x1080`과 `1440x1080`에 모두 일치합니다.
- PROBE에서 필터로 줄을 찾아 이동한 뒤 뒤로가기를 누르면 필터만 닫히고 이동한 위치와 강조가 유지됩니다. 필터가 없을 때만 PROBE를 종료합니다.
- CI의 android 잡이 폐기된 `tools` SDK 패키지를 요청해 실패하던 문제를 고쳤습니다.

## 검증과 해석 범위

0.8.0 버전에서 Debug 단위 테스트 339개를 통과했고, Release 빌드와 lint를 확인했습니다. APK의 버전·패키지와 기존 정식 인증서 일치를 검사했습니다.

CTS 케이스는 PR #76에서 Galaxy S25+ SM-S936N / Android 16 release 서명 빌드로 2회 전체 실행해 카메라 4대(0 BACK, 1 FRONT, 2·3 BACK), 프로파일 30개 녹화, FAIL 0을 확인했습니다. 드롭률 최대 1.1 %, 길이 3033~3053 ms(기대 3133 ms ±20 %)였고, CIF 프로파일 없음과 카메라 2·3의 2160P 없음은 SKIP입니다. 숫자가 아닌 카메라 ID(물리 카메라)는 `CamcorderProfile`이 다루지 못해 CTS와 같이 SKIP합니다. LEGACY 기기와 EXTERNAL 카메라 경로는 JVM 테스트로만 확인했습니다.

PROBE 필터 변경은 PR #78에서 같은 기기로 `REALTIME` 필터 → 항목 이동 → 뒤로가기 1회에 필터만 닫히고 위치가 유지됨을 확인했습니다. 이번 버전 번호 변경 후 새 카메라 측정은 수행하지 않았습니다.

# HAL CAM 0.13.1

화면에 적힌 숫자를 믿을 수 있게 만든 판입니다. 값이 잘리거나 겹쳐 잘못 읽히던 세 자리를 고쳤고, 값의 크기와 무관하게 같은 길이로 그려지던 결과 막대에 공유 축을 주었으며, 프레임이 멈춘 화면이 무슨 상태인지 말하게 했습니다. 앱을 손으로 눌러 가며 검토한 결과에서 나온 이슈들입니다.

## 설치

첨부된 `HAL-Camera-0.13.1.apk`를 기존 앱 위에 설치하세요. 앱 데이터와 실행 기록을 유지하려면 앱을 삭제하지 마세요.

| 항목 | 값 |
| --- | --- |
| 패키지 | `dev.halcamera` |
| 버전 | `0.13.1` · versionCode `145` |
| 지원 Android | Android 8.0 이상 · minSdk 26 / targetSdk 36 |
| 빌드 | 서명된 Release |
| 인증서 SHA-256 | `f2432413635645cc35e674e498e88ff518abb878065c21f17bb3c2128487b5c1` |

versionCode가 133에서 145로 건너뜁니다. 이번 검토 과정에서 기기에 올린 임시 빌드가 144까지 올라가 있어, 그보다 낮은 번호로는 앱을 지우지 않고 설치할 수 없기 때문입니다. 134부터 144까지는 배포된 적이 없습니다. versionCode는 단조 증가만 지키면 되므로 이후 판도 146부터 이어집니다.

저장 형식은 그대로입니다. run JSON은 schema 5, profile은 `camera2-standard-v2`이며 baseline과 calibration을 다시 만들 필요가 없습니다.

## 변경 사항

### 측정값이 잘리거나 겹쳐 읽히던 문제

- 진단 패널의 `Frame callback timeline`이 값 라벨을 각 점 중심에 그리면서 충돌을 피하지 않았습니다. PARTIAL과 BUFFER는 평시에도 몇 밀리초 안에 함께 도착하므로 `62.7`과 `67.5`가 겹쳐 `62.767.5` 한 덩어리로 읽혔습니다. 이제 겹칠 이웃끼리 묶어 `62.7 / 67.5`로 두 점 사이에 적습니다.
- PROBE의 값 열은 매다는 들여쓰기를 쓰는데, 기본 줄바꿈 전략이 그 들여쓰기가 줄 폭을 좁히기 전에 문단 전체를 재고 있었습니다. `10.00 diopters`는 마지막 글자가 화면 밖으로 나갔고, `-0.086577885`는 `-0.0865`와 `77885`로 쪼개져 측정한 적 없는 두 값처럼 보였습니다. 줄바꿈을 단순 전략으로 바꾸고 하이픈 분철을 껐습니다.
- CTS 실행 로그는 원래 좌우로 밀 수 있었지만 스크롤바도 가장자리 표시도 없어서, `fast close 11.`에서 끝난 줄이 거기서 끝난 값으로 읽혔습니다. 스크롤이 남아 있는 동안 가장자리가 흐려집니다([PR #144](https://github.com/TTolsun/hal-camera/pull/144)).

### 결과 막대의 축

- 막대가 행마다 자기 baseline에 맞춰 스케일을 잡고 있어서, 현재 값이 baseline보다 크면 언제나 80% 자리까지 찼습니다. `Open` 11 ms와 `First frame` 561 ms의 막대가 같은 길이로 그려졌다는 뜻입니다.
- 이제 같은 묶음 안에서 단위가 같은 지표끼리 축 하나를 공유합니다. 묶음의 최대값이 80% 자리에 오므로 두 실행이 아무리 벌어져도 채운 막대와 눈금이 트랙 안에 남습니다.
- 축을 묶음과 단위에서 끊은 이유는 `Preview`의 33 ms 간격이 `Capture`의 수백 ms와 한 축에 묶이면 사실상 0으로 뭉개지고, fps와 ms와 개수는 애초에 같은 축에 올릴 수 없기 때문입니다. 묶음 안에서 단위가 혼자인 지표는 자체 축을 쓰며, 막대 아래 설명이 그 사실을 적습니다([PR #142](https://github.com/TTolsun/hal-camera/pull/142)).

### 갤러리와 카메라 이름

- 갤러리 부제가 필터를 따라갑니다. 동영상 필터를 건 상태에서 `사진 8장 · 동영상 6개`로 남아 있던 줄이 이제 `동영상 6개`가 됩니다. 일반 모드와 선택 모드가 서로 다른 목록을 세던 것이 원인이었습니다.
- 전면 카메라가 둘인 기기에서 `Camera · 1 (Front)`와 `Camera · 3 (Front)`로 나와 목록만 보고는 구별할 수 없었습니다. 렌즈 이름을 붙이지 못한 카메라에는 HAL이 보고한 35 mm 환산 초점거리를 덧붙여 `Camera · 1 (Front · 26 mm)`처럼 적습니다. 역할 이름을 새로 지어내지 않은 이유는 20/35 mm 구간이 후면 모듈을 보고 고른 것이고, 두 전면 카메라가 같은 구간 안에서도 화각이 다를 수 있기 때문입니다.
- 최근 미디어 썸네일이 동영상일 때 재생 표시를 겹칩니다. 그전에는 접근성 설명에만 종류가 들어 있어 스크린 리더로는 알고 화면으로는 알 수 없었습니다([PR #143](https://github.com/TTolsun/hal-camera/pull/143)).

### 프레임이 멈춘 화면

- 녹화 중에 진단 패널을 열면 촬영 조작부가 통째로 숨겨져 정지 버튼과 경과 시간이 함께 사라졌습니다. 녹화는 계속 돌아가는데 끝낼 방법이 화면에 없었습니다. 이제 두 조작이 패널 머리글로 따라 올라옵니다.
- CTS 실행은 카메라를 닫으며 끝나고, 닫힌 카메라는 마지막 프레임을 표면에 남깁니다. 케이스가 기기의 카메라를 모두 순회하므로 그 프레임은 대개 전면 카메라의 것이었고, 화면을 닫을 때까지 결과 아래에 남아 있었습니다. 실행 중이 아닐 때 표면을 가리고 지금이 어느 상태인지 적습니다.
- 일시정지한 프리뷰도 마지막 프레임을 유지해 스스로 멈춘 프리뷰와 구별되지 않았습니다. 멈춘 프레임 위에 그 사실을 적습니다([PR #145](https://github.com/TTolsun/hal-camera/pull/145)).

## 검증 범위

[PR #142](https://github.com/TTolsun/hal-camera/pull/142)·[#143](https://github.com/TTolsun/hal-camera/pull/143)·[#144](https://github.com/TTolsun/hal-camera/pull/144)·[#145](https://github.com/TTolsun/hal-camera/pull/145)의 Android 빌드·단위 테스트·Lint, CLI 테스트와 문서 CI가 통과했습니다.

Galaxy S25+의 Android 16에서 직접 확인한 항목은 다음과 같습니다. 타임라인이 `54.4 / 56.0`처럼 합쳐 적는 것, PROBE가 `10.00 diopters (10.0 cm)`와 `-0.086577885`를 온전히 내놓는 것, 녹화 중 진단 패널 머리글의 `● REC 00:05`와 정지 버튼이 동작하는 것, CTS 실행이 끝나면 프리뷰 자리가 `실행이 끝나 카메라를 닫았습니다`로 바뀌는 것, 일시정지 상태에 가림막이 덮이는 것입니다.

확인하지 못한 항목은 세 가지입니다. CTS 로그의 페이드 가장자리는 코드 확인에 머물렀고, 최근 미디어 썸네일의 재생 표시와 전면 카메라의 환산 초점거리 표기는 이 판을 설치한 뒤에 보아야 합니다.

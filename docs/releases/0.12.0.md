# HAL CAM 0.12.0

Benchmark 화면이 판정을 먼저 보여 줍니다. 결과를 열면 "저하된 지표가 몇 개인지"가 첫 줄에 나오고, 핵심 지표 네 개는 baseline 눈금이 있는 막대로 표시됩니다.

## 설치

첨부된 `HAL-Camera-0.12.0.apk`를 기존 앱 위에 설치하세요. 앱 데이터와 실행 기록을 유지하려면 앱을 삭제하지 마세요.

## 변경 사항

### Benchmark 화면 재설계

- 결과 화면의 첫 줄이 판정입니다. `1 metric degraded`, `No degradation`, baseline이 없으면 `First run`을 표시하고, 무엇과 비교한 결과인지 그 아래에 적습니다.
- 핵심 지표 네 개(`Camera open`, `First frame`, `Still capture`, `Frame rate`)를 막대로 그립니다. 막대는 이번 run, 눈금은 baseline이므로 어느 쪽이 큰지 숫자를 읽지 않아도 보입니다.
- 전체 지표 표, validity flag, 파일 경로는 `All metrics`와 `Run info` 접힘 아래로 옮겼습니다. 저장되는 값과 CSV 범위는 바뀌지 않았습니다.
- 비교 화면은 0 기준선 좌우로 변화율 막대를 그립니다. 왼쪽이 개선, 오른쪽이 저하입니다. 백분율로 표시할 수 없는 지표(개수, 단위 불일치)는 글줄로 남습니다.
- 시작 카드가 측정 내용과 소요 시간을 한 문장으로 설명하고 발열·배터리 상태를 함께 보여 줍니다. profile ID와 preflight 판정은 `Details` 접힘 아래에 있습니다.
- 기기 온도가 높아(SEVERE) 시작이 막힌 카드는 5초마다 스스로 다시 확인합니다. 식으면 버튼을 누르지 않아도 시작이 다시 가능해집니다.
- 화면 문구는 라벨·버튼·지표 이름·판정 단어를 영어로, 설명과 안내 문장을 한국어로 씁니다. 판정 단어는 `degraded`입니다.
- Probe는 프리뷰(Live) 화면의 도구 메뉴에서만 엽니다. Benchmark 카드의 중복 진입 버튼을 없앴습니다.

### Profiling data 보관 개수

- `Settings`에서 보관할 profiling data 개수를 10·20·50·100·Unlimited 중에 고릅니다. 기본값은 Unlimited이므로 설정을 바꾸기 전에는 기존 동작과 같습니다.
- 한도를 넘으면 실행이 저장된 직후 오래된 것부터 삭제합니다. baseline으로 지정한 실행은 삭제하지 않습니다.

### CLI와 문서

- 앱이 `halcam` CLI 스킬을 함께 배포합니다([PR #124](https://github.com/TTolsun/hal-camera/pull/124)).
- `cts.run`이 suite 키를 호출 인자로 전달합니다([PR #126](https://github.com/TTolsun/hal-camera/pull/126)).
- CLI 오류 코드 문서를 실제로 마주치는 경우 중심으로 정리했습니다([PR #127](https://github.com/TTolsun/hal-camera/pull/127)).

## 검증 범위

[PR #125](https://github.com/TTolsun/hal-camera/pull/125)의 Android 빌드·단위 테스트·Lint, CLI 테스트와 문서 CI가 통과했습니다. Galaxy S25+의 Android 16에서 시작 카드, 실행, 결과 화면의 막대와 판정, Results에서 다시 연 결과, 비교 화면의 변화율 막대, `Profiling data limit` 설정과 복원을 확인했습니다.

이번 검증에서 확인하지 못한 항목은 두 가지입니다. 기기 온도가 SEVERE인 상태의 자동 재확인은 검증 중 기기가 그 온도에 도달하지 않아 확인하지 못했고, 보관 개수를 넘긴 실제 삭제는 기기에 저장된 실행이 한도보다 적어 JVM 테스트로만 검증했습니다.

# HAL CAM 0.8.1

LIVE 상단을 `API · 상태 · 도구 · 진단`으로 나누어 Benchmark·PROBE·CTS를 `도구` 메뉴의 독립 화면으로 옮겼습니다. 앱 코드 변경은 이 화면 배치 하나이며, 나머지는 문서와 개발 도구의 변경입니다.

## 설치

첨부된 `HAL-Camera-0.8.1.apk`를 설치하세요. 기존 정식 앱과 같은 인증서로 서명했으므로 기존 앱 위에 업데이트할 수 있습니다. 실행 기록과 baseline을 유지합니다.

| 항목 | 값 |
| --- | --- |
| 패키지 | `dev.halcamera` |
| 버전 | `0.8.1` · versionCode `12` |
| 지원 Android | Android 8.0 이상 · minSdk 26 / targetSdk 36 |
| 빌드 | 서명된 Release · debuggable=false |
| 인증서 SHA-256 | `f2432413635645cc35e674e498e88ff518abb878065c21f17bb3c2128487b5c1` |

파일 해시는 첨부된 `SHA256SUMS.txt`에서 확인합니다. PC CLI는 변경 없이 0.1.0을 사용하며 [0.6.0 릴리스의 wheel](https://github.com/TTolsun/hal-camera/releases/tag/v0.6.0)을 설치할 수 있습니다.

## 변경 사항

- LIVE 상단 줄에 `도구` 메뉴가 생기고 `Benchmark`, `PROBE`, `CTS`를 엽니다. `Benchmark`와 `CTS`는 LIVE 카메라를 닫고 `close(done)` 콜백을 받은 뒤 화면을 열며, 닫는 동안과 녹화·저장 중에는 메뉴를 비활성화합니다. `PROBE`는 카메라를 열지 않으므로 바로 엽니다.
- 기존 `Benchmark` 패널은 `진단`으로 이름이 바뀌고 READOUT·그래프·MARK·incident 같은 세션 의존 항목만 남습니다. 패널의 `벤치마크`·`카메라 사양`·`CTS 케이스 실행` 버튼은 `도구` 메뉴로 옮겨졌습니다.
- 문서: Camera2 닫기 중 logcat에 찍히는 `CameraDeviceImpl.onDeviceError` monitor contention 경고가 프레임워크 동작이며 앱 닫기 순서와 CLOSE 측정에 영향이 없음을 알려진 제약에 기록했습니다(#84). 반복 측정 비교를 Galaxy S25+ 실제 자료로 끝까지 확인한 결과와 해석 제한을 `docs/PROFILE-COMPARISON.md`에 추가했습니다(#4).
- 개발 도구: 새 화면·패키지에 담당 문서 요소가 없으면 `docs-check`가 실패하는 담당 요소 검사를 추가했고(#88), 가이드 사이트에 PROBE·CTS 페이지를 추가했습니다(#85).

## 검증과 해석 범위

0.8.1 버전에서 Debug 단위 테스트, `lintDebug`, Release 빌드를 확인했습니다. APK의 버전·패키지와 기존 정식 인증서 일치를 검사했습니다.

도구 메뉴는 PR #82에서 Galaxy S25+ SM-S936N / Android 16 release 서명 빌드로 확인했습니다. `Benchmark`·`CTS` 진입 시 카메라 0이 `IDLE` → `CLOSED`(약 260 ms) 뒤 화면이 열리고, `PROBE`는 즉시 열리며, 각 화면에서 돌아오면 프리뷰가 재시작됩니다. 녹화 중에는 `도구`가 비활성화됩니다. 같은 빌드로 2026-09-16에 CLI 벤치마크 5회를 실행했고 모두 비교·점수 적격이었습니다. `close(done)` 대기 시간은 HAL에 따라 다릅니다.

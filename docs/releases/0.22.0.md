# HAL CAM 0.22.0

Photo와 같은 화면 구성에서 Dual 프리뷰와 카메라별 동영상 저장을 사용합니다. Camera2 사진에는 RAW/DNG 출력을 추가했습니다.

## Installation

`HAL-Camera-0.22.0.apk`를 기존 앱 위에 설치합니다. 패키지는 `dev.halcamera`, versionCode는 `650`이며 Android 8.0 이상을 지원합니다. 기존 정식 인증서로 서명하고 `SHA256SUMS.txt`로 APK 해시를 제공합니다. 앱을 삭제할 필요가 없으며 업데이트 시 기존 데이터를 유지합니다.

## Changes

- 하단에 `Dual · P`와 `Dual · V`를 추가했습니다. Camera 1을 메인으로, Camera 2를 드래그할 수 있는 서브 프리뷰로 표시합니다. Photo의 기본 버튼 배치를 유지합니다.
- Camera2와 CameraX에서 Dual 비디오를 지원합니다. 두 카메라의 출력을 각각 무음 MP4로 저장합니다. CameraX Dual 비디오는 1280×720 H.264 구성을 사용합니다.
- Dual 프리뷰·녹화 중 화면을 켜 두고, Live Streams에는 실제 Dual 출력만 읽기 전용으로 표시합니다. Manual 탭 위치를 고정하고 CameraX의 미지원 Manual 진입을 막았습니다.
- RAW를 지원하는 Camera2 카메라에서 RAW_SENSOR를 DNG로 저장합니다. 프레임별 black/white level을 반영하며 Live 출력 표시와 Gallery의 RAW 표시를 추가했습니다.
- CameraX 종료 시 장치 해제를 개선했습니다. 검증되지 않은 내부 점수 초안을 제거했으며 성능 저하 판정은 명시한 baseline과의 비교로 확인합니다. JSON의 기존 점수 필드는 호환을 위해 남기고 새 기록에서는 null로 저장합니다.

## Validation and limits

Galaxy S25+ SM-S936N · Android 16 / API 36에서 Camera2·CameraX Dual 프리뷰와 MP4 두 개 저장, 서브 프리뷰 이동, Live Streams 진입·복귀와 Manual 버튼을 검증했습니다. 화면 꺼짐 시간을 15초로 설정한 검사에서도 Dual 녹화가 28초까지 유지됐으며 설정은 원래 값으로 복원했습니다.

Dual은 지원되는 논리·물리 카메라 조합에서만 동작합니다. `Dual · P`는 현재 프리뷰 전용으로 사진 셔터가 비활성화됩니다. 두 MP4의 시작 시각·길이가 정확히 같거나 센서가 동기화된다고 보장하지 않습니다. CameraX Dual 출력 설정은 고정이며 일반 Photo·Video의 Live Streams 설정과 별개입니다.

이번 UI 후속 검증에는 전체 CTS, 장시간 Benchmark, 가로 화면과 TalkBack 실행을 포함하지 않았습니다. 다른 기기와 Android 10 미만의 저장 경로는 별도 검증이 필요합니다.

자세한 범위는 [Dual 검증 기록](https://github.com/TTolsun/hal-camera/blob/v0.22.0/docs/validation/dual-mode-ui.md)과 [UI 일관성 검증 기록](https://github.com/TTolsun/hal-camera/blob/v0.22.0/docs/validation/ui-consistency.md)을 확인하세요.

## Release artifact checks

정식 versionCode 650 APK의 v2 서명을 검증했으며 인증서 SHA-256은 `f2432413635645cc35e674e498e88ff518abb878065c21f17bb3c2128487b5c1`로 기존 정식 릴리스와 일치합니다. APK의 패키지·버전·minSdk 26·targetSdk 36과 비디버그 설정을 확인했습니다. JVM 테스트는 app 638개와 ctsvendor 12개, 총 650개가 통과했고 lint와 문서 검사도 통과했습니다.

0.22.0 패키징 시점에는 연결된 기기가 없어 versionCode 650 APK 자체의 업데이트 설치를 재검증하지 못했습니다. 위 실기기 결과는 동일한 앱 코드에 테스트용 versionCode 642를 사용한 서명 빌드에서 확인한 내용입니다.

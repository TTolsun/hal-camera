# HAL CAM 0.6.0 코드리뷰와 배포 검증

2026-09-13 · 검토자: Codex. 구현 코드 `710393d02ba90497520fd4851c157cdb189479d2`를 0.5.1 main `0a1d71e8b27c021b05d794f82817063078696953`과 대조했다. 사람의 독립 승인으로 표시하지 않는다. 이 검토는 PR #58의 병합 전에 수행했다.

## 검토 결과

Provider의 호출자·URI·입력 검사, 명령 영속화와 중복 방지, Activity 전환·종료, 사진 저장 콜백, 벤치마크 완료·취소, Python ADB 인자와 다운로드 처리를 검토했다. 발견한 다음 문제를 수정하고 관련 테스트를 다시 수행했다.

| 발견 사항 | 수정과 확인 |
|---|---|
| PC 상태 확인과 CLEAR_TOP 사이에 작업이 시작되면 기존 benchmark를 중단할 수 있었다. | 별도 투명 Activity가 main thread에서 다시 검사한다. 실행 중 직접 launch에도 request·화면이 유지되었고 반복 실행도 통과했다. |
| Android가 launch task를 재사용하면 gate 실행 없이 기존 결과 화면에 머물렀다. | 새 task와 별도 affinity를 사용한다. UI·CLI 교대 10회와 취소 후 재실행을 확인했다. |
| 이전 Activity의 busy 알림이 현재 화면의 상태를 덮어쓸 수 있었다. | host 소유자를 확인하며 실제 UI 작업 상태도 실행 직전에 검사한다. UI 녹화·두 CLI 경합을 확인했다. |
| Activity 파괴 이후 도착한 close 완료 콜백이 report 저장을 생략할 수 있었다. | runner 완료 후 보고서 저장까지 IO executor를 유지한다. 뒤로 가기 후 partial JSON 회수를 확인했다. |
| 저장소 열기 실패·손상 파일·backup 복구와 상태 polling의 파일 IO가 충분히 구분되지 않았다. | AtomicFile 복구·확인과 메모리 snapshot을 추가했다. 영속화 실패는 STORE_FAILED로 중단하며 재시작 시 재실행하지 않는다. API 26·36에서 각 15개 저장소 검사가 통과했다. |
| 미설치 package의 `pm path` 종료 코드가 연결 오류로 변환되었다. | package 목록에서 정확히 일치하는 항목을 확인한다. 실제 미설치와 유사 이름 fixture를 검증했다. |
| 잘못된 상태·artifact 객체가 Python 예외로 종료될 수 있었다. | 타입과 완료 상태를 검증하고 PROTOCOL_ERROR로 반환한다. 손상 파일·경로 이동·기존 파일 덮어쓰기도 거부한다. |

재검토에서 알려진 미해결 P1·P2 항목은 없다. benchmark profile, stream spec, runner 순서, warm-up, 통계와 baseline 정의는 변경하지 않았다. UI·CLI 교대 10회는 동일 계약과 20개 지표를 유지했으며, 측정 성능의 동등성을 단정하지 않는다.

## 검증 근거

- Python 18개, JVM 267개, API 26·36의 instrumentation 각 15개가 통과했다.
- Debug·Release 빌드, lintDebug·lintRelease, testReleaseUnitTest를 확인했다.
- 문서 회귀·디자인·동기화 31개가 통과했고 실제 Qwen 연결 검사 1개는 기본값대로 건너뛰었다. 최신성·생성 일치·디자인 일치 검사가 통과했다.
- [기능 검증 기록](../validation/cli-device.md)에 USB·무선 사진, 정상·취소·시간 초과 benchmark, 앱 종료·재시작, UI 회귀와 10회 교대 측정을 기록했다.
- 배포 wheel을 별도 가상환경에 설치하고 `halcam --version`과 정식 앱의 `doctor`를 실행했다. CLI 0.1.0 / 앱 0.6.0 연결을 확인했다.

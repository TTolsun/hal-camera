# HAL CAM 0.9.0

CTS 화면이 케이스 목록으로 바뀌어 커스텀 케이스 다섯 종과 AOSP CTS 원문 케이스를 앱 안에서 실행합니다. PROBE에 request·result key 이름 목록이 생기고, 진단 패널에 앱 정보(About) 다이얼로그가 추가됐습니다.

## 설치

첨부된 `HAL-Camera-0.9.0.apk`를 설치하세요. 기존 정식 앱과 같은 인증서로 서명했으므로 기존 앱 위에 업데이트할 수 있습니다. 실행 기록과 baseline을 유지합니다.

| 항목 | 값 |
| --- | --- |
| 패키지 | `dev.halcamera` |
| 버전 | `0.9.0` · versionCode `13` |
| 지원 Android | Android 8.0 이상 · minSdk 26 / targetSdk 36. CTS 원문 케이스는 Android 14(API 34) 이상 |
| 빌드 | 서명된 Release · debuggable=false |
| 인증서 SHA-256 | `f2432413635645cc35e674e498e88ff518abb878065c21f17bb3c2128487b5c1` |

파일 해시는 첨부된 `SHA256SUMS.txt`에서 확인합니다. PC CLI는 변경 없이 0.1.0을 사용하며 [0.6.0 릴리스의 wheel](https://github.com/TTolsun/hal-camera/releases/tag/v0.6.0)을 설치할 수 있습니다.

## 변경 사항

- CTS 케이스 목록(#98): `도구 → CTS`가 케이스 목록을 열고, 카드를 고르면 케이스 하나를 실행해 같은 PASS·FAIL·SKIP 보고서를 냅니다. 커스텀 케이스는 `FastOnOff`(표준 열기와 빠른 재열기 5회씩, 첫 프레임 중앙값 비교), `Switching`(카메라 순회 5회 뒤 카메라마다 최대 CamcorderProfile로 3초 녹화), `AllSizeOnOff`(SurfaceHolder 크기 전부 열어 첫 프레임 확인), `StillPreviewCombination`(still × preview 조합), `VideoSnapshot`(녹화 중 정지 영상) 다섯 종입니다. 판정 규칙은 순수 Kotlin(`cts/*/…Rules.kt`)에 두고 JVM 테스트로 검증합니다.
- CTS 원문 케이스(#100): `:ctsvendor` 모듈이 AOSP `android16-release`의 camera2 CTS 소스(`RecordingTest`, `Camera2SurfaceViewTestCase`, `CtsCameraUtils`)를 그대로 담고 앱 프로세스 안의 JUnit 4로 실행합니다. `도구 → CTS`는 `커스텀 케이스`와 `CTS 원문 케이스` 중 하나를 고르며, 원문 케이스의 `@Test` 메서드를 reflection으로 나열합니다. 출처 커밋과 패치 7건, 재동기화 절차는 `ctsvendor/UPSTREAM.md`에 있습니다. 0.8.1의 Kotlin `기본 녹화` 케이스는 이 경로로 대체되어 제거됐습니다.
- PROBE(#97): `REQUEST · RESULT KEYS` 섹션(기본 접힘)에 `availableCaptureRequestKeys`·`availableCaptureResultKeys` 이름 목록을 찍습니다. 필터 일치 목록에서 여러 줄 값은 첫 줄과 남은 줄 수(`외 N줄`)를 붙입니다.
- 앱 정보(#99): 진단 패널 헤더의 ⓘ 버튼이 앱 이름·버전·용도·제작자 연락처를 보여주는 다이얼로그를 엽니다. 서명 블록을 누르면 메일 앱이 열립니다.
- LIVE(#92): 상단 바를 같은 폭의 3개 컬럼으로 나누어 `Camera2 · LIVE` 상태 텍스트가 화면 중심에 놓입니다.
- 내부 구조(#94, #96): `benchmark`를 `domain/`(순수 Kotlin)과 `platform/`(파일·CameraManager 경계)으로 나누고, CLI 화면 어댑터를 `cli/`로 옮겼습니다. `LayerIsolationTest`가 `domain/`의 `android.*`·`org.json` import를 검사합니다. 동작 변경은 없습니다.

## 검증과 해석 범위

0.9.0 버전에서 Debug 단위 테스트, `lintDebug`, Release 빌드를 확인했습니다. APK의 버전·패키지와 기존 정식 인증서 일치를 검사했습니다.

기기 검증은 모두 Galaxy S25+ SM-S936N / Android 16의 release 서명 로컬 빌드입니다. 커스텀 케이스 다섯 종은 2026-09-17에 카메라 4대에서 모두 PASS였습니다(`StillPreviewCombination`은 조합 324·300·264·286개, 약 29분). CTS 원문 `testBasicRecording`은 카메라 4대 × CamcorderProfile 7~8개를 3초씩 녹화·검증해 1분 58초에 PASS였고, `중단`은 두 경로 모두 2~4초 안에 끝났습니다. `RecordingTest`의 나머지 메서드 중 `UiAutomation`·`@TestApi` 때문에 초기화에서 실패하는 목록은 아직 확인하지 않았습니다. 케이스 실행 시간과 첫 프레임 수치는 HAL과 기기 온도에 따라 다릅니다.

# HAL CAM 0.13.0

벤치마크를 읽는 일에 집중한 판입니다. 조작점을 58개에서 35개로 줄였고, 결과 화면의 모든 지표를 막대로 그리며, 화면마다 달랐던 카메라 이름을 하나로 통일했습니다.

## 설치

첨부된 `HAL-Camera-0.13.0.apk`를 기존 앱 위에 설치하세요. 앱 데이터와 실행 기록을 유지하려면 앱을 삭제하지 마세요.

| 항목 | 값 |
| --- | --- |
| 패키지 | `dev.halcamera` |
| 버전 | `0.13.0` · versionCode `133` |
| 지원 Android | Android 8.0 이상 · minSdk 26 / targetSdk 36 |
| 빌드 | 서명된 Release |
| 인증서 SHA-256 | `f2432413635645cc35e674e498e88ff518abb878065c21f17bb3c2128487b5c1` |

versionCode가 114에서 133으로 건너뜁니다. 개발 중 기기에 임시 빌드가 132까지 올라가 있어, 그보다 낮은 번호로는 앱을 지우지 않고 설치할 수 없기 때문입니다. 115부터 132까지는 배포된 적이 없습니다. versionCode는 단조 증가만 지키면 되므로 이후 판도 134부터 이어집니다.

## 변경 사항

### 벤치마크 기능 축소

- 반복 측정 비교 화면을 없앴습니다. 여러 기기의 분포를 모으지 않기로 하면서, 여러 실행을 묶어 순열검정을 수행하는 화면과 외부 JSON 가져오기의 쓸모가 사라졌습니다. 비교는 baseline과 이번 실행, 두 개 사이에서만 이루어집니다.
- 시작 카드의 `Details` 접힘, Build·Commit·메모 입력 세 칸, 결과·비교 화면의 복사 버튼, Results의 Profile 필터를 함께 없앴습니다.
- 조작점이 58개에서 35개로 줄었습니다([PR #129](https://github.com/TTolsun/hal-camera/pull/129)).

### 결과 화면

- 측정한 모든 지표를 막대로 그립니다. `Launch`·`Preview`·`Capture`·`Stability`·`3A`로 묶으며, 숫자만 나열하던 `All metrics` 접힘은 없앴습니다. 값과 기준을 나란히 읽는 것이 이 화면의 목적인데, 숫자 행은 막대보다 그 일을 못 합니다.
- 막대 옆 숫자는 표본의 중앙값이며 캡션 `median`이 그 사실을 적습니다. 이름에 이미 통계가 들어 있는 `Interval p50`·`Interval p95`와 개수 지표에는 캡션을 붙이지 않습니다.
- `Preview` 묶음은 `Frame rate`가 먼저 오고 그 간격 행이 뒤따릅니다. `29.8 fps`가 `34 ms`보다 먼저 읽히기 때문이며, 판정 자체는 간격 행이 가집니다.
- 3A 항목이 관측 창 안에 수렴하지 못하면 값 대신 `timeout`을 적고 막대를 비웁니다. 이때 저장된 값은 수렴 시각이 아니라 창의 길이라서, 막대를 그리면 창과 수렴을 견주는 그림이 됩니다.
- `실행 정보` 접힘은 서로 반복되던 문장 일곱 개 대신 라벨과 값 아홉 줄입니다. validity flag를 코드가 아니라 뜻으로 적습니다(`충전 중`, `빌드 이름 없음`). 코드는 계약이므로 JSON과 CSV에는 그대로 남습니다([PR #132](https://github.com/TTolsun/hal-camera/pull/132)).

### Results 목록

- 각 행이 monospace 여섯 줄에서 두 줄로 바뀌었습니다. 첫 줄은 실행 시각과 배지, 둘째 줄은 사실 한 줄입니다. 빌드 이름을 입력한 실행에만 그 줄이 하나 더 붙습니다.
- 배지는 `★ Baseline`과 `▲ N degraded`이며, 판정이 없으면 `측정 무효`·`비교 불가`·`점수 제외` 중 하나를 적습니다. 비교 가능하고 점수에도 들어가는 실행에는 배지가 붙지 않습니다.
- run id와 profile, 원본 flag는 행이 아니라 행이 여는 결과 화면에 있습니다([PR #130](https://github.com/TTolsun/hal-camera/pull/130)).

### 보관 한도

- `Settings`의 이름이 `Profiling data limit`에서 `Data limit`으로 짧아졌고, 다섯 항목 목록 대신 슬라이더로 고릅니다.
- 눈금은 10부터 100까지 10 단위이며, 그 끝에 `∞`로 표시하는 Unlimited가 한 칸 더 있습니다. 이전의 10·20·50·100은 같은 거리에 10, 30, 50의 간격을 놓아 슬라이더의 약속을 어겼습니다.
- 기본값은 Unlimited이므로 설정을 바꾸기 전에는 기존 동작과 같습니다.

### 도구 순서와 카메라 이름

- `도구` 메뉴가 `Probe` · `CTS` · `Benchmark` 순서로 열립니다. HAL이 무엇을 할 수 있다고 선언하는지, 그 선언대로 통과하는지, 실제로 얼마나 걸리는지의 순서이며, 문서 사이트의 탭도 같은 순서를 씁니다.
- 카메라 이름을 화면마다 다르게 부르던 것을 하나로 합쳤습니다. 같은 카메라를 Live는 `후면 · 0`, Benchmark는 `Rear main · ID 0`, Probe는 `후면 · MAIN · FULL`(ID 없음), CTS는 `ID 0`으로 적고 있었습니다.
- 이제 줄이 허락하면 `Camera · 0 (Wide · Rear)`, 칸이 좁으면 `Camera · 0`입니다. 괄호 안은 렌즈와 방향이며, 렌즈는 35mm 환산 초점 거리로 추론한 `Wide`·`UWide`·`Tele`입니다. 전면 카메라는 렌즈를 추론하지 않으므로 `Camera · 1 (Front)`처럼 방향만 적습니다.
- 논리 카메라 뒤의 물리 카메라는 `Camera · 0.5 (Wide · Rear) · physical`처럼 점으로 이은 키를 씁니다([PR #131](https://github.com/TTolsun/hal-camera/pull/131)).

### 문서

- 아키텍처 문서에 뭉쳐 있던 화면 설명을 각 탭으로 옮겼습니다. 결과 화면과 Results는 Benchmark 페이지가, Live와 갤러리 배치는 `APP-UI.md`가 담당하고, 아키텍처에는 데이터가 지나가는 경로만 남겼습니다.
- 문서와 코드를 전수 대조해 어긋난 서술 아홉 곳을 고쳤습니다. 존재하지 않는 `ProfileLibrary` 클래스, 실제와 다른 버튼 이름, 업스트림 패치 개수, Probe 필터의 예시 문자열 등입니다.

## 검증 범위

[PR #129](https://github.com/TTolsun/hal-camera/pull/129)·[#130](https://github.com/TTolsun/hal-camera/pull/130)·[#131](https://github.com/TTolsun/hal-camera/pull/131)·[#132](https://github.com/TTolsun/hal-camera/pull/132)의 Android 빌드·단위 테스트·Lint, CLI 테스트와 문서 CI가 통과했습니다.

Galaxy S25+의 Android 16에서 `도구` 메뉴의 순서, Live 상단의 `Camera · 0 · Live`, Probe의 카메라 목록 여섯 개가 모두 통일된 표기로 나오는 것, 결과 화면의 카테고리별 막대와 `실행 정보` 접힘, Results 목록의 두 줄 행과 배지, `Data limit` 슬라이더의 양 끝을 확인했습니다.

이번 검증에서 확인하지 못한 항목은 세 가지입니다. 기기 온도가 SEVERE인 상태의 자동 재확인은 기기가 그 온도에 도달하지 않아 확인하지 못했고, 보관 개수를 넘긴 실제 삭제는 저장된 실행이 한도보다 적어 JVM 테스트로만 검증했으며, 3A의 `timeout` 표시는 관측 창 안에 수렴하지 않는 조건을 만들지 못해 코드 확인에 머물렀습니다.

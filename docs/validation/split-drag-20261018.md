# Split 화면 끌기 검증

센서 이름표를 250ms 누른 뒤 약 56dp를 끌면 원하는 방향의 배치를 제안하도록 수정했습니다. 패널 이동량은 손가락 이동량과 같습니다. 기존에는 패널 중심이 미리보기 영역의 가장자리 22%에 진입해야 해서 좌우 배치에서 위로 옮길 때 영역 높이의 약 28%를 이동해야 했습니다. 새 판정은 화면의 위치나 높이 대신 시작 위치에서의 방향과 거리를 사용합니다.

## 실제 카메라 화면

Galaxy S25+ (`SM-S936N`, Android 16), Camera2, 후면 0과 전면 1의 Multi P에서 확인했습니다. 0.29.2 기반 수정 APK를 기존 release 서명으로 덮어 설치했습니다.

| 시나리오 | 결과 |
| --- | --- |
| 기존 앱에서 전면 이름표를 위로 60dp 이동 | 좌우 배치의 오른쪽 칸이 계속 제안됐습니다. |
| 수정 앱에서 같은 거리로 이동 | 상단 절반의 테두리와 `Release · Top` 안내가 나타났고, 놓은 뒤 전면 화면이 위로 이동했습니다. |
| 후면 화면을 오른쪽·아래·위·왼쪽으로 각각 60dp 이동 | 각 방향의 배치와 화면 순서가 적용됐습니다. 마지막에는 원래 후면 왼쪽·전면 오른쪽 배치로 복원했습니다. |
| 이름표를 잡고 위로 12dp 이동 | 기존 좌우 배치와 화면 순서를 유지했습니다. |
| 위로 60dp 이동 후 시작 위치로 복귀하고 놓기 | 기존 좌우 배치와 화면 순서를 유지했습니다. |

스크린샷은 로컬 검토 자료로 확인했습니다. 카메라 영상이 포함되어 저장소에 추가하지 않았습니다. 사진·동영상 저장 검사는 이번 변경의 범위에 포함하지 않습니다. 카메라 3개 이상의 대각선 격자 전환은 JVM 검사로만 확인했습니다.

## 자동 검사

- `testDebugUnitTest`: app JVM 테스트 845개가 통과했습니다. 전환 거리, 네 방향 배치, 대각선 흔들림, 전환 유지·해제 경계, 작은 영역과 3개 이상 패널을 검사했습니다.
- `lintDebug`: 문제가 없었습니다.
- `assembleRelease`, `assembleDebugAndroidTest`: 빌드가 통과했습니다. 기기 검사용 테스트 APK도 기존 앱과 같은 서명으로 빌드했습니다.
- `am instrument -w -e split_drag true dev.halcamera.test/dev.halcamera.cli.CliStoreInstrumentation`: 실제로 붙어 있는 Android View에서 짧은 탭, 이동 없는 길게 누르기, 56dp 전환, 손가락과 같은 이동량, 시작점 복귀, ACTION_CANCEL, 비활성화된 상태의 놓기, 추가 손가락과 뷰 분리가 통과했습니다. 이 검사는 카메라를 촬영하지 않습니다.
- 문서 회귀 검사 37개, 담당 요소 검사, 생성 일치와 사이트 일치 검사가 통과했습니다. `check --build`의 최신성 단계는 변경된 근거에 대한 검토 기록 9건이 필요해 실패했습니다. `tools/docgen/README.md`의 사람 검토 규칙에 따라 기존 `accepted` 기록은 유지했습니다. 변경 동작은 구조 원본과 사용자 안내에 반영했습니다.

조작 방법은 [Multi 사용 안내](../../guide/live.md#여러-카메라를-함께-촬영하세요)에서 확인할 수 있습니다.

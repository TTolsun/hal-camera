# 전체 코드·문서 구조 검토 — 2026-10-17

전체 저장소를 대상으로 참조·중복·계층 경계와 현재 문서의 계약을 검사했습니다. 확인된 미사용 선언과 CTS 화면 중복을 제거하고, PC 집계 도구가 앱의 schema 5와 녹화 유효성 규칙을 따르도록 수정했습니다. 이 기록은 모든 코드가 SOLID를 완벽히 만족한다는 인증이 아닙니다.

## 범위와 방법

## 수정한 계약 불일치

1. 앱은 schema 5를 쓰지만 PC 집계기는 3·4만 받았습니다. 이제 3·4·5를 읽으며 미래 버전은 계속 거부합니다. 녹화 지표의 값과 프로파일 ID가 CSV에 보존되는지 검사합니다.
2. `RECORD_NOT_MEASURED`는 점수 산정만 막는 앱의 알려진 플래그인데 PC 집계기는 비교까지 막았습니다. 현재 플래그 표와 맞췄으며 알 수 없는 플래그의 fail-closed 처리는 유지합니다.
3. 저장된 validity 버전이 없을 때의 기본값을 현재 `validity-v3`로 맞췄습니다. 파일에 기록된 기존 버전은 보존합니다.
4. README와 .omm의 schema 4·표준 V1·Activity 두 개 설명을 현재 schema 5·표준 V2·Activity 세 개에 맞췄습니다. 삭제된 stateName 설명과 잘못된 문서 경로도 정리했습니다.

## SOLID와 문서 책임 경계

측정·판정은 순수 Kotlin, 플랫폼 접근은 어댑터, 표시 방식은 UI에 남깁니다. CTS 공통 뷰에는 실행 판단을 넣지 않았습니다. 엔진의 기능별 인터페이스와 주입된 실행 Driver를 유지하므로 이번 정리는 인터페이스를 불필요하게 확대하지 않습니다. 대형 Activity의 길이 자체를 책임 위반으로 단정하거나 실행 수명주기를 한꺼번에 재작성하지 않았습니다.

문서에는 SOLID를 코드처럼 기계적으로 적용하지 않고 주제별 책임과 원본 위치를 확인했습니다. 현재 CLI 계약은 guide, 과거 설계는 docs/design, 실측은 docs/validation, 배포 이력은 docs/releases에 둡니다. .omm·원고·생성 HTML은 같은 설명의 독립 사본이 아니라 파이프라인의 입력과 출력이므로 삭제하지 않습니다. Python과 Kotlin은 독립 배포되는 구현이므로 런타임 소스 파싱으로 묶지 않고 CI 계약 비교로 차이를 탐지합니다.

## 검증과 한계

- `assembleDebug`, `assembleDebugAndroidTest`, `testDebugUnitTest`, `lintDebug`가 통과했습니다. JVM 테스트는 826개이며 실패는 없습니다. Android lint는 오류 0개·경고 159개입니다.
- Python 집계 테스트 10개와 CLI 테스트 88개가 통과했습니다.
- 문서 회귀 테스트 33개와 문서 파이프라인 6단계(디자인·사실·최신성·담당 요소·생성·사이트 검사)가 통과했습니다.
- 문서 검토 기록은 사용자의 리뷰 요청에 따라 Codex가 코드와 대조한 기록입니다. 사람의 승인이나 새로운 기기 실측을 뜻하지 않습니다.
- 이번 작업에서는 기기에서 CTS를 재실행하지 않았습니다. 테스트 APK 빌드는 기기 실행 성공을 의미하지 않습니다. 화면 공통화는 기존 뷰 크기·덮개·스크롤 속성을 유지하는 코드 검토로 확인했습니다.
- 자동 검색으로 남은 데드코드가 전혀 없다고 보장하지 않습니다. 동적 진입점, 기기별 Camera2 동작과 기존 lint 경고는 별도 검증 범위입니다.
- 최종 diff 리뷰에서 JsonMaps.s가 빈 문자열과 문자열 `null`도 결측값으로 취급함을 확인해 Python 기본값 처리와 회귀 테스트에 반영했습니다. 외부 Sourcery 리뷰는 사용량 한도로 생략되었으며 이 기록의 리뷰 주체는 Codex입니다.

# Dual 모드와 RAW UI 검증

2026-10-09에 Galaxy S25+ (SM-S936N), Android 16 / API 36에서 검증했습니다. 화면 배율은 640 dpi, 글꼴 배율은 1.15였습니다. 별도 검증 APK의 versionCode는 642이며 저장소의 릴리스 버전은 바꾸지 않았습니다.

## 실기기 결과

| 시나리오 | 결과 |
| --- | --- |
| Live에서 Dual · P 진입 | logical 0의 physical 5·6을 1440×1080으로 열었습니다. Camera 1은 메인, Camera 2는 둥근 서브 프리뷰에 표시됐습니다. |
| 서브 프리뷰 드래그 | 위치를 옮길 수 있었고 Dual · V 전환·카메라 교환·앱 복귀 뒤에도 위치가 유지됐습니다. 녹화 중에도 이동했습니다. |

| Dual · V 녹화·정지 | A_cam5와 B_cam6 MP4가 같은 식별자로 저장됐습니다. 두 파일 모두 1440×1080 H.264이며 길이는 18.654초와 18.587초였습니다. |

| Gallery | 새 MP4 네 개와 RAW 배지가 표시됐습니다. |

첫 녹화의 MP4 두 개를 PC로 가져와 ffprobe로 H.264·1440×1080을 확인했습니다. ffmpeg로 전체 프레임을 디코딩했으며 두 파일 모두 오류 없이 끝났습니다. 오디오 트랙은 없습니다. 길이 차이에서 알 수 있듯 파일 시작과 종료의 정확한 동기를 보장하지 않습니다.

카메라 출력은 어두운 장면에서 확인했습니다. 영상 선명도나 노출 품질을 판정한 결과는 아닙니다. 다른 기기의 물리 출력 조합, API 28 저장 권한, 저장 공간 부족과 인코더 오류를 주입한 시나리오는 검증하지 않았습니다.

## 자동 검사

Photo UI 유지 보정 후 같은 기기에서 다시 확인했습니다. Camera2·Callback·Lab, 갤러리, 셔터, 카메라 선택, 모드와 Save Events 버튼의 화면 좌표가 Photo와 같았습니다. 예를 들어 셔터 중심은 (720, 2548), 모드 행은 y=2676–2868이었습니다. 프리뷰가 화면 전체를 채우며 별도의 Dual 제목이나 패널을 표시하지 않습니다. Callback에서 실제 Shutter·Metadata 타임라인이 표시됐고 Save Events의 5초 수집 후 ZIP 저장 완료를 확인했습니다. 갤러리 진입·복귀와 동일 셔터 위치의 녹화 시작·정지도 확인했습니다. 녹화 시간은 기존 모드 행을 대체합니다.

- `testDebugUnitTest`: app 638개와 ctsvendor 12개가 통과했습니다.
- `lintDebug`와 서명 release 빌드가 통과했습니다.
- 문서 coverage, generate 일치 검사와 site build 검사가 통과했습니다.
- 통합 `check --build`는 변경 근거에 대한 기존 검토 기록이 최신이 아니므로 실패했습니다. 사용자 가이드와 구조 설명은 갱신했으며, `tools/docgen/README.md`에서 사람에게 맡긴 `verify --accept`는 실행하지 않았습니다.

JVM 검사 결과는 두 카메라가 특정 기기에서 함께 열리는지를 입증하지 않습니다. 그 동작은 위 실기기 결과로 별도 기록했습니다.

## CameraX 추가 검증

같은 Galaxy S25+·Android 16에서 CameraX Dual · P의 physical 5·6 프리뷰를 1440×1080으로 확인했습니다. Dual · V는 1280×720으로 두 프리뷰와 카메라별 MP4를 제공합니다. Preview 두 개와 VideoCapture 두 개를 동시에 bind하는 구성은 이 기기에서 거부되어, 두 Preview를 각각 화면과 인코더에 전달하는 GPU relay를 사용했습니다. 카메라 제어는 CameraX가 담당합니다.

29.802초 녹화의 A_cam5·B_cam6 파일 두 개를 PC에서 검사했습니다. 두 파일 모두 H.264·1280×720이며, 어두운 장면의 실제 전달률은 약 15 fps였습니다. ffmpeg 전체 디코딩은 오류 없이 완료됐습니다. 오디오 트랙은 없습니다. CameraX Dual · P↔Dual · V, Camera2↔CameraX, CameraX Photo 복귀와 듀얼 재진입을 확인했습니다. 기존 Photo와 동일한 UI 배치를 유지했습니다. 다른 기기의 CameraX 물리 카메라 출력 조합은 검증하지 않았습니다.

최종 빌드에서 녹화 중 서브 프리뷰를 왼쪽에서 오른쪽으로 이동한 뒤 홈 화면으로 나갔습니다. 공통 식별자 `HAL_20261009_015915_515_1c7737`의 A_cam5·B_cam6 MP4가 저장됐으며, 앱 복귀 후 두 프리뷰가 약 15 fps로 재개되고 오른쪽 서브 프리뷰 위치가 유지됐습니다.

## 머지 전 코드 리뷰

CameraX 세션의 상태 관찰자를 종료 시 제거하고, Activity가 중지돼도 장치 종료를 기다리도록 수정했습니다. OPENING 상태에서 종료한 경우에도 다음 세션을 먼저 열지 않도록 CameraState와 장치 onClosed를 함께 확인합니다. Camera2 또는 CameraX의 영상 전달이 실패하면 녹화 쌍을 무효화하여 정상 저장으로 보고하지 않습니다. 수정 후 JVM 테스트 650개, lintDebug, release 빌드가 통과했습니다.

실기기 UI 스크린샷은 촬영 장면을 포함하므로 공개 저장소에 게시하지 않고 로컬 검토 자료로 보관했습니다.

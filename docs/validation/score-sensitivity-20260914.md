# S25+ 점수 민감도와 취소·복귀 검증

2026-09-14에 Galaxy S25+ SM-S936N, Android 16, HAL CAM 0.6.0 release에서 17건을 수집했습니다. 정상 완료 16건의 점수 계산과 취소 1건의 점수 미부여 동작을 확인했습니다. 앱 소스와 점수 계수는 변경하지 않았습니다. 이번 기록은 [#9](https://github.com/TTolsun/hal-camera/issues/9)의 추가 근거이며, 해당 이슈와 상위 [#4](https://github.com/TTolsun/hal-camera/issues/4)의 완료 판정은 아닙니다.

## 실측 조건과 결과

후면 메인 camera 0, `camera2-standard-v1`, 1920×1080, 고정 30 fps를 사용했습니다. 계약은 `camera2-standard-v1|metrics-0.3|nearest_rank|elapsedRealtimeNanos`입니다. 모든 실행은 실제 비충전·절전 해제 상태였고 `thermal_start/max/end`는 모두 0이었습니다. 사용자가 휴대폰 고정과 조명 상태, USB 분리를 확인했습니다. 조도계의 lux 측정값은 없습니다.

| 조건 | 횟수 | 점수 범위 | 중앙값 | 해석 |
|---|---:|---:|---:|---|
| 정상 조명 | 3 | 852–863 | 853 | 정상 완료했습니다. |
| 첫 저조도 | 3 | 853–862 | 861 | 정상 범위와 겹쳤습니다. |
| 추가 저조도 | 3 | 841–858 | 843 | 중앙값은 낮지만 범위가 일부 겹쳤습니다. |
| 카메라 점유 경쟁 | 3 | 860–867 | 864 | Android가 HAL CAM에 카메라를 넘긴 뒤 정상 완료했습니다. |
| 제한된 CPU 부하 | 3 | 847–867 | 849 | 발열에 따른 성능 제한은 관측되지 않았습니다. |
| 의도적 CLI 취소 | 1 | null | 해당 없음 | 부분 결과를 보존하고 점수를 부여하지 않았습니다. |
| 부하 제거·취소 후 정상 복귀 | 1 | 853 | 853 | 새로운 실행이 정상 완료했습니다. |

추가 저조도의 시간순 점수는 858·843·841점이었습니다. 노출 부하 중앙값은 약 95,700으로 정상 약 2,383의 40배였고, 첫 저조도 약 15,467보다 높았습니다. 프레임 간격은 추가 저조도에서 약 33.51 ms, 정상에서 약 33.34 ms였습니다. 프리뷰 정지(H.5)와 카메라 오류(H.9)는 모두 0이었습니다. 조명 차이는 확인했지만 현재 점수에 포함된 처리 성능 지표의 변화는 작았습니다.

카메라 경쟁은 별도 시험 앱의 camera 0 점유와 500 ms 간격의 재접근으로 만들었습니다. Android가 시험 앱의 점유를 해제한 뒤 HAL CAM에 카메라를 넘기고 시험 앱의 재접근을 거부하는 로그를 확인했습니다. 이 우선순위 경쟁 상황의 완료 동작을 확인한 것이며, 점유 경쟁으로 HAL CAM의 성능이 저하되었다는 근거는 아닙니다.

CPU 부하는 작업 스레드 6개, 측정 전 60초 부하, 시험당 최대 150초로 제한했습니다. SEVERE 또는 배터리 42°C에서 중단하도록 설정했습니다. 충전·발열 보고값을 강제로 바꾸지 않았습니다. 실제 thermal 값은 모두 0이었으므로 발열에 따른 성능 제한 검증은 남습니다.

취소 실행 `20260914-204911-683`은 `ABORTED`, `HARD_FAILURE`, `INSUFFICIENT_SAMPLES`, `PREFLIGHT_MISMATCH` 플래그를 기록했습니다. 측정·비교·점수 적격 여부가 모두 false이고 전체 점수·점수 규칙·모든 지표 점수는 null이었습니다. 부분 JSON 62,389 bytes를 회수했으며 다음 실행 `20260914-204955-334`는 853점으로 정상 완료했습니다.

## 회귀 테스트와 자료 범위

[축약 실측 자료](../../app/src/test/resources/score-sensitivity-20260914.tsv)는 원본 JSON 17건에서 점수 입력과 저장된 기대값을 추출한 TSV입니다. 첫 13열은 조건, 실행 ID, 원본 SHA-256, 배터리 시작·종료, 취소 사유, 플래그, 측정·비교·점수 적격 여부, 전체 점수, 점수 규칙, 노출 부하입니다. 나머지 20열의 이름은 `지표 ID:category:unit`, 각 셀은 `value;n;timeout;score`입니다. `null`은 값 없음, 플래그의 `-`는 빈 목록을 뜻합니다. 기대 점수는 설치된 release가 저장한 값이며 테스트 실행 중 다시 생성하지 않습니다.

[MeasuredScoreSensitivityTest](../../app/src/test/java/dev/halcamera/benchmark/MeasuredScoreSensitivityTest.kt)는 17개 실행 각각에 대해 다음을 검사합니다.

- 실제 `ScoreComposer.apply`가 전체 점수와 20개 지표 점수를 재현하는지 확인합니다. 정보성 지표와 취소 실행의 null도 검사합니다.
- schema 4의 Map 인코딩·디코딩이 결과와 적격 여부를 보존하는지 확인합니다.
- 복원된 결과의 점수 표시와 취소 결과의 점수 숨김을 확인합니다.

공통 점수 입력인 앱 버전·모델·카메라·계약·비충전·절전 해제·thermal 0을 테스트에 고정했습니다. 측정 이벤트, 원시 샘플, 통계 보조 필드, 광학 정보 등 점수에 쓰이지 않는 필드는 재생하지 않으며 기존 테스트 fixture의 대체값을 사용합니다. 따라서 JVM 검사는 카메라 엔진, JSON 문자열 파서, 실제 파일 저장이나 CLI 전송을 재실행하는 검사가 아닙니다. 원본 17건의 파일 크기·SHA-256과 저장 점수는 별도 현장 감사에서 확인했습니다. 원본과 상세 시험 로그는 로컬에 보관하며, 장치 연결 정보·시험 서명키·APK는 PR에 포함하지 않습니다. TSV의 SHA-256은 원본을 식별하는 값이며 공개 자료만으로 원본 전체를 검증할 수는 없습니다.

설치 APK와 검사한 작업 폴더의 release APK SHA-256은 모두 `8b781668e70ae0ed9b55bed2a9dc3c654cb690e93d713412adebfb423d130a92`였습니다. 해당 작업 폴더의 소스 HEAD는 `5f543a7`입니다. 기기 빌드는 `BP4A.251205.006.S936NKSSCCZH2`, 보안 패치는 2026-08-05입니다. 이 정보는 검사 대상의 출처 기록이며 재현 빌드 증명은 아닙니다.

## 남은 검증

조건별 3회 표본이며 정상·스트레스 점수 범위가 겹칩니다. 저조도에서 일관된 점수 저하, 실제 발열과 점유 경쟁에 따른 성능 저하의 충분한 근거, 여러 제조사·성능군의 5–10개 기기 데이터가 남아 있습니다. 점수 적격 플래그만으로 정상 조명 학습 표본이라고 판단할 수 없으며, 이번 표본은 기존 calibration에 추가하지 않았습니다. 이 테스트는 현재 `score-v1-draft`의 동작을 보존하며 공개 점수의 민감도 승인 기준을 대신하지 않습니다.

검증 종료 후 시험 앱 제거와 HAL CAM의 `busy=false`를 확인했습니다. 임시로 허용받은 무선 디버깅을 다시 비활성화했습니다. 마지막 비활성화 명령 후 연결이 즉시 offline으로 바뀌어 설정값 재조회 응답은 받지 못했습니다.

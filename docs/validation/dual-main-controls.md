# Dual 프리뷰 제어와 Callback 검증

2026-10-09, SM-S936N(Android 16)에서 Camera2 Dual의 공통 줌, 메인 EV·AE 잠금, 두 센서 사진 저장을 확인했다. CameraX에서는 공통 줌 UI와 양쪽 프리뷰 Callback을 확인했다.

## 변경 동작

- 줌은 논리 카메라에 요청하여 두 물리 출력에 공통 적용한다. EV, AF·AE 잠금, 터치 측광과 수동 설정은 메인 물리 카메라의 지원 키로만 요청한다.
- Camera2 사진은 기존 프리뷰 세션이 닫힌 뒤 두 YUV 출력을 구성하고, 하나의 STILL 요청에 두 센서를 포함한다. 같은 결과의 논리 또는 물리 타임스탬프에 대응하는 두 버퍼를 받아 JPEG 두 장으로 저장한다. 한쪽만 받거나 다른 프레임이면 저장하지 않는다.
- 사진 이름은 같은 식별자와 `A_cam<id>`, `B_cam<id>`를 사용한다. 저장 중 실패하면 생성한 항목을 제거한다. 촬영 뒤 프리뷰를 복구한다.
- Callback은 Shutter, Metadata, Main/Sub display와 Main/Sub photo를 구분한다. Display는 화면의 SurfaceTexture 갱신 시각이며 HAL 버퍼 도착 시각으로 표시하지 않는다. 센서 시각은 프레임 대응에만 사용하고 앱 시각과 빼지 않는다.
- 일반 프리뷰의 줌·제어·수동 패널을 재사용한다. Callback이나 제어 메뉴를 펼치면 PiP를 남은 공간으로 이동·축소한다.

## 기기 관찰

| 시나리오 | 결과 |
| --- | --- |
| Camera2 Wide 5 + Tele 6, 2배 줌 | Wide crop `[1020,765][3060,2295]`, Tele crop `[912,684][2736,2052]`를 보고했다. 각각 원본의 가로·세로 절반이다. |
| 메인 EV +0.2 | 메인 결과의 보정 단계는 2, 보조는 0이었다. |
| 메인 AE 잠금 | 메인 `aeLock=true`, 보조 `false`를 확인했다. |
| 2배 줌 사진 | 두 센서의 JPEG 파일이 같은 이름 식별자로 저장됐고 프리뷰가 복구됐다. |
| Callback | 두 엔진에서 Main/Sub display 수치가 표시됐다. Camera2 사진에서는 Main/Sub photo 수신을 같은 Event Frame에 표시했다. |

줌 변경 후 사진 버퍼가 논리 타임스탬프를 사용하는 경우를 처음에 놓쳐 타임아웃이 발생했다. 같은 촬영 결과의 논리 타임스탬프도 허용하도록 수정한 뒤 2배 줌 사진 저장을 재확인했다.

## 자동 검증

`assembleRelease`, `testDebugUnitTest`, `lintDebug`가 통과했다. 리뷰 후 JVM 테스트는 644개이며 실패·오류는 0개다. 새 회귀 검사는 물리 시각이 다른 두 버퍼, 동일 요청의 논리 시각 대응, 한쪽 누락·인접 프레임 거부와 Callback 프레임 대응을 다룬다. 특히 서로 다른 센서가 인접 프레임에서 같은 타임스탬프를 보고해도 센서 ID로 올바른 프레임에 연결한다.

사용자의 리뷰·머지 요청에 따라 변경 코드와 가이드를 대조하고 검토자를 Codex로 기록했다. `docflow check --build`로 최신성·담당 요소·생성 결과·사이트를 검사한다. 리뷰에서는 ImageReader를 하나씩 보관하여 부분 초기화 실패 시에도 해제하도록 고쳤고, 카메라 오류 뒤 사진 저장이나 프리뷰 재구성을 하지 않도록 막았다.

SM-S936N에서 공통 줌·두 센서 사진 Callback을 확인한 캡처는 로컬에 보관하며 공개 저장소에 포함하지 않는다. 이후 기본 화면의 설명 문구를 줄였으며 해당 문구 수정과 리뷰 보완분은 빌드로 검증했다. 기기에는 다른 작업의 versionCode 651이 설치되어 최종 versionCode 650 빌드로 덮어쓰지 않았다.

## 지원 범위와 남은 검증

CameraX의 메인 개별 제어와 두 센서 사진은 아직 지원하지 않으며 화면에 Camera2 지원 범위를 안내한다. 공통 줌과 Callback은 두 엔진에 연결했다. 공유 플래시와 사용자 지정 WB는 현재 Dual 제어에서 제공하지 않는다.

사진 출력은 공통 YUV 크기를 사용한다. 선택된 프리뷰 크기와 센서 최대 사진 해상도의 일치를 보장하지 않는다. 촬영 세션 전환 동안 프리뷰가 잠시 정지한다. 이 기기의 센서 동기화 유형은 APPROXIMATE이며, 같은 요청과 같은 보고 타임스탬프가 실제 노출 시각의 완전한 일치를 증명하지 않는다.

수동 설정의 모든 조합, 다른 렌즈 조합, 회전·백그라운드 전환 중 촬영, 녹화 중 줌의 하드웨어 검증은 별도로 필요하다. 일반 프리뷰와 모든 기능이 동등하다고 판정하지 않는다.

문서 재검토 절차는 [문서 파이프라인](../../tools/docgen/README.md)을 따른다.

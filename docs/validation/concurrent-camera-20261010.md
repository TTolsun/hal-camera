# 전면·후면 동시 카메라 검증 — 2026-10-10

## 기능 정의 정정

최종 기능명은 **Multi**입니다. 기존 Dual 모드를 대체하며 2개 이상의 카메라 장치를 각각 열어 사용합니다. 최대 장치 수 설정은 `Live Streams → Multi → Maximum camera devices`에 있습니다. 보조 프리뷰 배치 버튼은 `Inset`입니다.

**PIP**는 메인과 하나 이상의 서브 프리뷰를 보이는 구도 그대로 합성하여 사진·영상으로 저장하는 별도 기능을 뜻합니다. 현재 Multi는 카메라별로 사진을 저장하며 PIP 합성 저장을 구현하지 않습니다. 아래의 PIP 명칭은 정정 전 로컬 검증 기록입니다. 최종 Multi 변경도 실기기 검증 대기 상태입니다.

## 최종 PIP 변경 — 실기기 검증 대기

최종 기능명은 PIP입니다. Live Streams의 `PIP → Maximum camera devices`에서 `All available` 또는 2 이상 상한을 선택하고 Apply로 저장합니다. PIP의 Streams 버튼에서도 같은 설정을 열며, 뒤로 가기는 초안을 버립니다. 설정 화면을 열기 전에 모든 장치의 종료를 기다립니다.

공개 Logical Camera ID를 각각 열고, 광고된 동시 조합의 모든 부분집합 중 상한 이내의 조합을 제시합니다. 지원 조합을 우선하고 장치 수가 큰 순서로 표시합니다. 화면·사진·종료 처리는 선택한 장치 수에 따라 동작하며 주 화면 외의 영상은 보조 영상 열이나 세로 분할로 배치합니다. 실제 세션 구성은 계속 사전 검사합니다. 최대값 설정은 기기의 동시 실행 능력을 늘리지 않습니다.

사용자가 외출하며 실기기 검증을 복귀 후 진행하도록 요청했습니다. 이 최종 변경은 로컬 JVM 테스트·lint·release 빌드와 문서 검사로 검증했으며 기기에 설치하지 않았습니다. 아래의 과거 실기기 결과는 최종 PIP 설정과 3대 이상 동작을 검증한 결과가 아닙니다.

복귀 후에는 다음 순서로 확인합니다.

1. 최종 APK를 기존 앱에 덮어 설치하고 Live의 PIP 진입과 카메라 조합 목록을 확인합니다.
2. Live Streams에서 최대값을 변경한 뒤 뒤로 가면 저장되지 않고, Apply를 누르면 재진입·앱 재시작 후에도 유지되는지 확인합니다.
3. PIP의 Streams로 이동한 동안 CameraService의 활성 장치가 비고, 복귀 시 새 상한 이내의 조합이 열리는지 확인합니다.
4. 지원 조합의 프리뷰·사진 저장·Swap·보조 영상 이동·분할을 확인합니다. 3대 이상은 해당 조합을 광고하고 출력 구성을 지원하는 기기에서 별도로 검증합니다.
5. 미지원 조합·촬영 중 종료·홈 복귀에서 오래된 프리뷰나 카메라 자원이 남지 않는지 확인합니다.

로컬 테스트는 4대 조합의 11개 부분집합, 최대값 2·3에 따른 제한, 2~6대 레이아웃의 경계·겹침·분할 높이, 3대의 open/streaming/close 장벽을 포함합니다.

## Multi 통합 후 추가 확인

후속 UI 요청에 따라 Live의 Dual · P/V 진입을 하나의 Multi로 교체했습니다. 후면·후면과 후면·전면은 같은 조합 목록과 PIP/분할 화면을 사용합니다. 공개 camera ID마다 별도 장치를 열며 Physical 출력으로 대체하지 않습니다. 기존 물리 출력 코드는 CLI 호환 경로에 남아 있습니다. 현재 화면은 두 장치를 선택하며, 세 장치의 수명주기 장벽은 JVM 테스트로 검증했습니다. 세 장치 화면과 녹화는 이번 Multi 범위에 포함하지 않았습니다.

S25+에서 Rear 0 + Front 1/3과 Rear 0 + Rear 2가 같은 목록에 표시되는 것을 확인했습니다. Rear 0 + Rear 2는 사전 검사에서 거부되었고, 오류 표시 후 CameraService 활성 클라이언트가 비어 있었습니다. 따라서 후면끼리의 동시 프리뷰 성공을 주장하지 않습니다. 조합 변경·오류·종료 시 이전 프리뷰를 숨겨 다른 카메라의 영상처럼 보이지 않도록 했습니다.

Multi 변경 후 JVM 테스트 714개(ConcurrentPlanTest 9개), lint와 release 빌드, 문서 회귀 테스트 33개를 통과했습니다. 아래는 통합 전 전면·후면 경로의 상세 검증 기록입니다.

이 기록은 #170의 Camera2 전면·후면 동시 프리뷰와 독립 사진 저장 구현을 검증합니다. 기존 후면 물리 카메라 Dual과는 별도 경로입니다. 센서 동기 촬영이나 합성 동영상은 제공하지 않습니다.

## 환경

- Galaxy S25+ (SM-S936N), Android 16 / API 36을 사용했습니다.
- `ff11245b` 기반 `codex/issue170-concurrent`의 서명된 release APK를 기존 앱에 덮어 설치했습니다. 앱 데이터는 유지했습니다.
- 기기가 광고한 조합은 후면 0 + 전면 1, 후면 0 + 전면 3입니다. 두 조합 모두 카메라별 1280×720 프리뷰와 1920×1440 JPEG 구성을 사전 검사에서 허용했습니다.
- 사용자의 기기 단독 사용 허가 후 다른 테스트 앱과 UI 자동화를 중단하고 검증했습니다.

| 두 사진 저장 | 각 조합에서 독립 JPEG 두 개와 공통 group ID의 JSON 생성을 확인했습니다. |

| 뒤로 가기 | 두 장치의 DISCONNECT 이후 Live의 카메라 0이 CONNECT되는 순서를 확인했습니다. 전면 클라이언트가 남지 않았습니다. |
| CameraX에서 진입 | Camera2 전환 안내를 확인한 뒤 두 프리뷰가 열렸습니다. |
| 촬영 직후 뒤로 가기 | 두 카메라 모두 `Capture cancelled: screen closed`로 JSON에 기록되었고 Live 카메라 0만 활성 상태로 남았습니다. 성공한 촬영으로 표시하지 않았습니다. |

다른 테스트 앱이 겹쳐 실행되던 초기 관측에서는 카메라 3의 소유권 상실 안내와 두 카메라 해제를 확인했습니다. 이 관측은 재현 시점을 통제한 경합 시험으로 간주하지 않습니다.

두 조합의 최종 촬영 group ID는 각각 `HAL_concurrent_d76cf798-7e5e-4661-9926-ba020d176270`, `HAL_concurrent_b3c6bd51-20d0-4249-bdfa-5715b31010a8`입니다. 종료 중 취소 group ID는 `HAL_concurrent_9b204821-3b3d-4d59-bcd0-0ce4c38b40fd`입니다. JSON은 `Download/HALCamera`, JPEG는 `DCIM/HALCamera`에 저장됩니다. JSON은 camera ID, 요청·구성 크기, timestamp source, 이미지·센서 시각 또는 실패 사유를 구분하며 `sensorSynchronized`는 false입니다.

실기기 스크린샷과 빌드 로그는 작업 공간의 비공개 검증 자료로 보관했습니다. 실제 카메라 영상은 저장소에 포함하지 않았습니다.

## 남은 하드웨어 검증 범위

API 30 미만 기기, 동시 조합을 광고하지 않는 기기, 세션 사전 검사가 거부되는 조합은 이번 기기에서 검증하지 못했습니다. 따라서 해당 시나리오는 실기기 PASS나 지원 불가로 인한 SKIP으로 기록하지 않습니다. 강제로 유발한 open/configure 실패, 사진 한쪽만 실패하는 상황, 저장소 쓰기 실패와 제한 시간 만료도 실기기 미검증입니다. 순수 상태 테스트의 통과를 이러한 하드웨어 시험의 대체 결과로 해석하지 않습니다.

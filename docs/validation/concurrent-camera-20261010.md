# 전면·후면 동시 카메라 검증 — 2026-10-10
## 현재 Live PIP와 선택창 검증

SM-S936N, Android 16에서 2026-10-10 13:35~14:45에 확인했습니다. 이 절이 현재 동작이며 아래 Physical 전용·별도 화면 기록은 이전 구현 이력입니다.

- PIP 목록에 Physical 2·5·6과 Service 1·2·3을 표시하고 하나만 선택합니다. Service 1을 선택하면 MainActivity의 기존 Live에 전면 영상을 합성합니다.

- Photo에서 Video로 바꾸면 메인 0과 PIP 1을 모두 닫고 다시 열었습니다. 같은 Live 화면에 선택한 PIP가 복원됐습니다. 모드 전환과 PIP 단독 변경의 수명주기가 구분됩니다.

ISO 800 직접 입력, WB Custom 적용·초기화와 Multi 상세창 왕복도 확인했습니다. 모든 Service 조합, Multi의 공유 Service 소스, 3대 이상, 큰 시스템 글꼴, 장시간 녹화는 이번 최종 APK의 실기기 검증 범위에 포함하지 않았습니다.

아래 기록은 당시 구현과 검증 범위를 보존합니다. Physical 전용 선택, 별도 화면 진입, PIP 비활성 조건과 미검증 목록은 현재 사양이 아닙니다. 현재 사용법은 [Live 가이드](../../guide/live.md)를 따릅니다.

### Physical PIP 실기기 확인 — 2026-10-10 13시

SM-S936N, Android 16에서 release APK를 데이터 삭제 없이 갱신하여 확인했습니다. 실제 검증 중 TextureView의 native buffer가 합성 출력 크기와 달라 화면 왼쪽 아래에만 영상이 그려졌습니다. EGL 대상 크기를 조회하여 viewport를 설정하고, JPEG는 출력 크기의 별도 pbuffer에서 읽도록 수정한 뒤 같은 기기에 재설치했습니다.

- Single Camera 0에서 Physical 2·5·6 선택 목록을 확인했고, Physical 2를 선택한 프리뷰와 합성 JPEG 저장을 확인했습니다. 수정 후 영상은 프리뷰 영역 전체에 표시됐습니다.
- Single PIP의 무음 H.264 MP4(848×1280, 16.49초)를 저장하고 디코딩했습니다. 녹화 중 오른쪽 위에서 왼쪽 아래로 끈 Physical 화면이 영상 프레임에도 반영됐습니다.
- Multi 0+1은 기본 분할로 표시됐으며 Camera 1의 PIP는 비활성 상태였습니다. PIP를 끈 상태에서 JPEG 두 개를 저장했습니다.
- Multi의 Camera 0에 Physical 2를 추가한 뒤 Camera 1 영역까지 드래그해도 Physical 화면이 Camera 0 하단 경계에 머물렀습니다. 합성 후면 JPEG(1280×816)와 독립 전면 JPEG가 별도 파일로 저장됐습니다.
- 같은 Multi 세션에서 후면 PIP MP4(1280×816, 10.22초)와 전면 MP4(1280×818, 10.24초)가 각각 생성됐습니다. 두 파일의 H.264 스트림을 확인하고 후면 프레임을 디코딩하여 합성과 위치를 확인했습니다.

화면 캡처, JPEG, MP4와 디코딩 프레임은 저장소 밖 로컬 검증 폴더에 보관했습니다. 통화 화면이 나타난 뒤 화면 조작을 중단했습니다. 최대 장치 수 설정의 실기기 왕복, CameraX 전환, 여러 Physical 동시 선택, 3대 이상 장치, 장시간 녹화, 회전·미러 판별용 피사체 검증은 이번에 완료하지 않았습니다. 후면 피사체가 가까워 흐릿하므로 방향·초점 품질까지 통과한 것으로 해석하지 않습니다.

수정 후 JVM 테스트와 lint, release 빌드는 통과했습니다. 아래 로컬 구현 기록의 실기기 미검증 문구는 이 확인 이전 상태입니다.

## Single / Multi의 Physical PIP — 최종 로컬 구현

Single의 Camera2·CameraX 선택 옆 PIP 버튼은 Logical capability와 Physical ID가 있는 장치에만 활성화합니다. Multi는 독립 장치를 기본 분할하고 장치별 PIP 버튼으로 Physical 출력을 선택합니다. Physical 사각형은 부모 Logical 좌표 안에만 존재하며 드래그와 Move 모두 같은 경계를 적용합니다.

사진·영상은 Logical 장치별 파일입니다. PIP가 켜진 장치는 메인과 선택한 Physical 영상을 동일한 GPU draw 경로로 프리뷰·JPEG·무음 MP4에 합성합니다. PIP JPEG는 합성 프리뷰 크기이고 센서 최대 해상도가 아닙니다. CameraX에서 PIP를 선택하면 현재는 Camera2로 전환을 확인합니다. 화면 종료는 장치 onClosed와 합성 입력 해제·녹화 저장 완료를 기다립니다.

이 변경 이후 실기기는 조작하지 않았습니다. 아래의 이전 프리뷰·사진 관측은 새 GPU 합성 및 MP4 녹화를 검증한 결과가 아닙니다. 로컬 JVM 테스트 721개, lint·release 빌드, 문서 회귀 33개와 6단계 문서 검사를 통과했습니다. 추가 JVM 테스트는 부모 경계, 다른 Logical 장치의 Physical ID 거부, 여러 보조 프리뷰 배치, hit test, producer 회전·미러 행렬에 따른 비율을 검증합니다.

복귀 후 다음 하드웨어 검증이 필요합니다.

1. Single의 Logical / 비논리 ID를 바꿔 PIP 버튼 활성 상태와 Physical 선택 목록을 확인합니다. CameraX의 명시적 Camera2 전환도 확인합니다.
2. Multi가 분할로 시작하는지, Logical 장치별 PIP 선택이 독립적인지, 다른 장치 영역으로 보조 영상이 넘어가지 않는지 확인합니다.
3. 고정된 피사체로 프리뷰·저장 JPEG·MP4의 방향, 미러, 크롭, 보조 영상 위치를 비교합니다. PIP off 장치와 on 장치가 섞여 있어도 파일 수가 CameraDevice 수와 같은지 확인합니다.
4. 녹화 중 드래그·Move와 녹화 종료·홈 이동·뒤로 가기를 확인합니다. MP4 재생·길이·프레임율과 장시간 발열도 측정합니다.
5. 실제 HAL이 Logical + 선택 Physical 출력 조합을 거부하거나 프레임이 오지 않는 경우 명시적 실패·타임아웃 및 자원 해제를 확인합니다. 3대 이상 장치와 여러 Physical 출력은 지원 기기에서 별도로 검증합니다.

이하 항목은 기능 정의가 바뀌기 전의 이력입니다.

## 기능 정의 정정

최종 기능명은 **Multi**입니다. 기존 Dual 모드를 대체하며 2개 이상의 카메라 장치를 각각 열어 사용합니다. 최대 장치 수 설정은 `Live Streams → Multi → Maximum camera devices`에 있습니다. 보조 프리뷰 배치 버튼은 `Inset`입니다.

**PIP**는 메인과 하나 이상의 서브 프리뷰를 보이는 구도 그대로 합성하여 사진·영상으로 저장하는 별도 기능을 뜻합니다. 현재 Multi는 카메라별로 사진을 저장하며 PIP 합성 저장을 구현하지 않습니다. 아래의 PIP 명칭은 정정 전 로컬 검증 기록입니다. 최종 Multi 변경도 실기기 검증 대기 상태입니다.

## 최종 PIP 변경 — 실기기 검증 대기

최종 기능명은 PIP입니다. Live Streams의 `PIP → Maximum camera devices`에서 `All available` 또는 2 이상 상한을 선택하고 Apply로 저장합니다. PIP의 Streams 버튼에서도 같은 설정을 열며, 뒤로 가기는 초안을 버립니다. 설정 화면을 열기 전에 모든 장치의 종료를 기다립니다.

공개 Logical Camera ID를 각각 열고, 광고된 동시 조합의 모든 부분집합 중 상한 이내의 조합을 제시합니다. 지원 조합을 우선하고 장치 수가 큰 순서로 표시합니다. 화면·사진·종료 처리는 선택한 장치 수에 따라 동작하며 주 화면 외의 영상은 보조 영상 열이나 세로 분할로 배치합니다. 실제 세션 구성은 계속 사전 검사합니다. 최대값 설정은 기기의 동시 실행 능력을 늘리지 않습니다.

사용자가 외출하며 실기기 검증을 복귀 후 진행하도록 요청했습니다. 이 최종 변경은 로컬 JVM 테스트·lint·release 빌드와 문서 검사로 검증했으며 기기에 설치하지 않았습니다. 아래의 과거 실기기 결과는 최종 PIP 설정과 3대 이상 동작을 검증한 결과가 아닙니다.

복귀 후에는 다음 순서로 확인합니다.

1. 최종 APK를 기존 앱에 덮어 설치하고 Live의 PIP 진입과 카메라 조합 목록을 확인합니다.
2. Live Streams에서 최대값을 변경한 뒤 뒤로 가면 저장되지 않고, Apply를 누르면 재진입·앱 재시작 후에도 유지되는지 확인합니다.
3. PIP의 Streams로 이동한 동안 CameraService의 활성 장치가 비고, 복귀 시 새 상한 이내의 조합이 열리는지 확인합니다.
4. 지원 조합의 프리뷰·사진 저장·Swap·보조 영상 이동·분할을 확인합니다. 3대 이상은 해당 조합을 광고하고 출력 구성을 지원하는 기기에서 별도로 검증합니다.
5. 미지원 조합·촬영 중 종료·홈 복귀에서 오래된 프리뷰나 카메라 자원이 남지 않는지 확인합니다.

로컬 테스트는 4대 조합의 11개 부분집합, 최대값 2·3에 따른 제한, 2~6대 레이아웃의 경계·겹침·분할 높이, 3대의 open/streaming/close 장벽을 포함합니다.

## Multi 통합 후 추가 확인

후속 UI 요청에 따라 Live의 Dual · P/V 진입을 하나의 Multi로 교체했습니다. 후면·후면과 후면·전면은 같은 조합 목록과 PIP/분할 화면을 사용합니다. 공개 camera ID마다 별도 장치를 열며 Physical 출력으로 대체하지 않습니다. 기존 물리 출력 코드는 CLI 호환 경로에 남아 있습니다. 현재 화면은 두 장치를 선택하며, 세 장치의 수명주기 장벽은 JVM 테스트로 검증했습니다. 세 장치 화면과 녹화는 이번 Multi 범위에 포함하지 않았습니다.

S25+에서 Rear 0 + Front 1/3과 Rear 0 + Rear 2가 같은 목록에 표시되는 것을 확인했습니다. Rear 0 + Rear 2는 사전 검사에서 거부되었고, 오류 표시 후 CameraService 활성 클라이언트가 비어 있었습니다. 따라서 후면끼리의 동시 프리뷰 성공을 주장하지 않습니다. 조합 변경·오류·종료 시 이전 프리뷰를 숨겨 다른 카메라의 영상처럼 보이지 않도록 했습니다.

Multi 변경 후 JVM 테스트 714개(ConcurrentPlanTest 9개), lint와 release 빌드, 문서 회귀 테스트 33개를 통과했습니다. 아래는 통합 전 전면·후면 경로의 상세 검증 기록입니다.

이 기록은 #170의 Camera2 전면·후면 동시 프리뷰와 독립 사진 저장 구현을 검증합니다. 기존 후면 물리 카메라 Dual과는 별도 경로입니다. 센서 동기 촬영이나 합성 동영상은 제공하지 않습니다.

## 남은 하드웨어 검증 범위

API 30 미만 기기, 동시 조합을 광고하지 않는 기기, 세션 사전 검사가 거부되는 조합은 이번 기기에서 검증하지 못했습니다. 따라서 해당 시나리오는 실기기 PASS나 지원 불가로 인한 SKIP으로 기록하지 않습니다. 강제로 유발한 open/configure 실패, 사진 한쪽만 실패하는 상황, 저장소 쓰기 실패와 제한 시간 만료도 실기기 미검증입니다. 순수 상태 테스트의 통과를 이러한 하드웨어 시험의 대체 결과로 해석하지 않습니다.

## CameraX Single PIP 추가 검증

`fff6c981` 기반 CameraX PIP 변경을 같은 SM-S936N, Android 16에서 서명 release APK로 검증했습니다. CameraX는 1.6.2이며 Camera2로 전환하지 않고 ConcurrentCamera로 두 장치를 엽니다. 이 절은 앞선 Camera2·Multi 기록과 별도입니다.

| 시나리오 | 관찰 결과 |
|---|---|
| 메인 후면 0의 PIP 선택창 | 전면 Service 1·3만 표시되었고 Physical 목록이나 Camera2 전환 확인창은 없었습니다. |
| 0 + 1, 0 + 3, 메인 1 + 보조 0 | 각 조합에서 CameraX 표시와 두 프리뷰가 유지되었습니다. 입력 프리뷰는 960×720으로 협상했습니다. |
| PIP 이동·Photo→Video·보조 ID 변경 | 이동한 정규화 위치가 모드·보조 ID 변경 후에도 유지되었습니다. |
| 합성 사진·녹화 | JPEG와 MP4 프레임을 로컬에서 열어 동일 PIP 위치와 UI 미포함을 확인했습니다. 출력은 590×1280이며 MP4는 H.264 19.47초와 AAC 19.46초 트랙을 포함했습니다. 오디오 트랙 존재만 확인했으며 음질·입술 동기는 평가하지 않았습니다. |
| PIP Off와 일반 촬영 | Preview 1440×1080·YUV 640×480·JPEG 4080×3060으로 복구되어 일반 사진 저장이 성공했습니다. |
| PIP Off·On, 홈 이동·복귀 | CameraX PIP 프리뷰가 다시 열렸으며 활성 화면의 엔진·메인 ID가 유지되었습니다. |

최종 빌드를 다시 설치한 뒤 Camera2 일반 사진과 CameraX PIP 사진에서 저장 성공 안내가 표시되고 4초 후에는 사라지는 것을 확인했습니다. 일반 YUV·JPEG·RAW 출력을 모두 끈 상태에서도 PIP JPEG가 저장되었고 안내가 자동으로 사라졌습니다. 검증 후 일반 출력 설정을 복원했습니다. Camera2 Physical 2 PIP에서 CameraX로 전환하면 지원하지 않는 보조 소스를 복원하지 않고 일반 CameraX 프리뷰가 열렸습니다. PIP 메인 화면 터치 후 AF 상태 변화를 확인했으나 측광 영역의 좌표 정확도를 계측하지는 않았습니다.

최종 구현은 JVM 726개, lint, release 빌드와 GitHub Android CI를 통과했습니다. 타임아웃·카메라 경합·저장 실패를 강제로 유발하는 하드웨어 시험은 미검증입니다. 자동 검증 통과를 이 시험의 대체 결과로 해석하지 않습니다.

실제 카메라 영상이 포함된 사진·MP4·스크린샷은 비공개 로컬 검증 자료에만 보관했습니다. 다른 모델이나 CameraX가 조합을 광고하지 않는 기기의 성공을 주장하지 않습니다.

# 앱·CLI 사용성 수정과 모의 사용 평가

앱에서 저장 결과를 다시 찾는 경로와 CLI 실패 후 다음 행동을 명확히 했습니다. 사용자 요청에 따라 하나의 서브에이전트가 주의 분산 후 복귀, 이전 단계 망각, 기술 용어에 익숙하지 않은 상황을 가정하고 앱 화면에서 다음 행동을 선택했습니다. 주 에이전트가 선택한 행동을 기기에서 실행했습니다. 실제 ADHD 참가자 연구가 아니며, 임상적 효과나 사용자 성공률을 산출하지 않았습니다.

## 변경한 동작

| 발견한 문제 | 수정 |
| --- | --- |
| 썸네일이 저장물 목록으로 가는 버튼인지 불명확했습니다. | Live·Dual에 사진·영상 라벨을 추가했습니다. 라벨도 누를 수 있고 버튼 비활성 상태를 함께 표시합니다. 최소 72dp 슬롯은 큰 글자에 맞춰 늘어납니다. |
| 사진·영상 저장 안내와 연사 결과가 주의를 돌린 사이 사라졌습니다. | 저장 완료와 연사 종료 결과를 자동으로 숨기지 않습니다. 새 촬영 또는 새 CLI 카메라 작업에서는 이전 결과를 지웁니다. 화면 재생성 이후의 결과 보존을 보장하지는 않습니다. |
| 연사 시작 방법을 첫 화면에서 발견하지 못했습니다. | 사진 모드 준비 상태에 한 번 누르는 사진 촬영과 길게 누르는 연사 안내를 추가했습니다. 진행·결과·AEB 표시가 우선합니다. |
| 영상 저장 실패를 일시적 토스트로만 알렸습니다. | 활성 Live에서는 실패 안내를 유지하고 Save Events · ZIP으로 진단을 저장하는 다음 행동을 안내합니다. 이미 닫힌 카메라는 기존 토스트를 유지합니다. |
| 과거 측정과 ZIP의 위치가 불명확했습니다. | Run History에 이전 측정 결과라는 설명을 추가했습니다. ZIP 완료 창에 앱 내부 저장 여부, Lab → ZIP Archives 경로와 Save as의 의미를 표시했습니다. |

CLI는 무인자 실행에 짧은 시작 안내를 먼저 표시하고, `run --help`에 완전한 예시를 제공합니다. `doctor`는 연결뿐 아니라 카메라 권한·잠금·사용 중 상태를 확인합니다. 비활성 CLI나 만료된 요청에 같은 실패 명령을 반복하도록 안내하지 않습니다. 보관 제한 미리보기에는 변경되지 않았다는 문구와 Python CLI 문법의 명시적 적용 명령을 표시합니다. shell `status`·`cancel`은 종료 오류가 있어도 남아 있는 파일과 `fetch` 경로를 보여 주며 실패 종료 코드는 유지합니다.

## 에뮬레이터 관찰과 모의 사용자 선택

환경은 Android 16/API 36, `sdk_gphone64_x86_64`, 검증용 versionCode 659입니다. 사용자 APK 서명 자료를 복사하지 않고 기존 설정을 메모리에서 참조해 빌드했습니다. 초기 설치 전부터 에뮬레이터에 있던 미디어를 보존했습니다.

| 과제 | 관찰과 평가 | 근거 |
| --- | --- | --- |
| 사진 촬영 후 다른 일을 보고 돌아오기 | 8초 이상 경과 후 저장 안내가 남았습니다. 모의 사용자가 사진·영상 라벨을 골랐고 글자 자체를 눌러 갤러리로 이동했습니다. | [저장 안내](usability-20261009/photo-saved.png), [갤러리](usability-20261009/gallery-ready.png) |
| 연사 후 손을 떼기 | 촬영 종료 · Burst · 1 saved와 일반 셔터를 확인했습니다. 1은 촬영 결과 수이며 JPEG/YUV 파일 수와 같다고 간주하지 않았습니다. 초기 시도는 화면 복귀 직후 준비 전 입력이어서 동작하지 않았고, 준비 후 재시도했습니다. | [연사 결과](usability-20261009/burst-result.png) |
| 과거 측정 찾기 | 이전 측정 결과 설명을 보고 Run History를 선택했습니다. 이 AVD에는 측정 데이터가 없어 목록 진입과 빈 상태만 확인했습니다. | [Lab](usability-20261009/lab.png), [빈 기록](usability-20261009/history.png) |
| 진단 ZIP 저장 후 다시 찾기 | 완료 안내에서 Close → Lab → ZIP Archives를 선택했습니다. 완료 창과 같은 파일명을 목록에서 확인했습니다. | [완료 창](usability-20261009/events-saved.png), [ZIP 목록](usability-20261009/zip-list.png) |
| 큰 글자 | 시스템 글자 배율 2.0에서 사진·영상 라벨의 잘림·겹침이 없었습니다. 검사 후 1.0으로 복구했습니다. | [Live 200%](usability-20261009/live-font200.png) |

녹화 시작 처리와 REC 시간·정지 사각형은 구분됐지만 이 에뮬레이터 실행에서는 영상 저장이 실패했습니다. [녹화 중](usability-20261009/record-running.png)과 [수정 전 실패 토스트](usability-20261009/record-stop.png)를 기록했습니다. 화면만으로 기술적 실패 원인을 에뮬레이터 자체로 확정하지 않았습니다. 실패 안내 유지 수정은 이 관찰에서 도출했습니다. 수정 빌드에서는 같은 저장 실패 후 8초 이상 지나도 안내와 진단 경로가 남는 것을 [재확인](usability-20261009/failure-persistent.png)했습니다. [연사 시작 안내](usability-20261009/burst-hint.png)를 추가한 화면에서는 모의 사용자가 외부 설명 없이 길게 누르기를 선택했습니다. 손을 떼는 중단 방법의 최초 발견까지 검증한 것은 아닙니다.

## 실기기 검증

Galaxy S25+ SM-S936N, Android 16/API 36에 기존 데이터를 보존하는 업데이트 설치를 했습니다. 앱 UI에서 사진 저장, 3초 길게 누르기 후 연사 중단과 5회 저장 결과, 영상 시작·정지·저장 성공을 확인했습니다. 영상 저장 후 최신 썸네일의 접근성 설명도 video로 변경됐습니다. 실기기 화면에는 개인 공간이 포함돼 공개 자료에 넣지 않았습니다.

같은 기기에서 Python CLI `doctor`는 준비 상태와 34개 명령을 반환했습니다. `settings.limit`의 10개 보관 미리보기는 변경 없음, 삭제 예정 목록, 동일 serial을 보존한 적용 명령을 표시했습니다. `confirm=true` 적용은 실행하지 않았습니다.

## 자동 검사와 범위

- Python CLI·shell 회귀 검사 73개가 통과했습니다.
- JVM 테스트 693개, Android lint, release APK 빌드가 통과했습니다.
- 문서 회귀 검사 33개와 `docflow check --ci` 7단계가 통과했습니다. 최종 APK SHA-256은 `b531da2be87dfdf46840fb7524cd1e270231a2c501896bb9c3727e5895c5d48b`입니다.
- 모의 평가에서 갤러리 첫 항목을 최신으로 판단한 것은 정렬 관례에 의존했습니다. 촬영 시각·정렬 안내는 후속 개선 후보입니다.
- Dual 라벨은 공통 뷰를 사용하지만 이번 화면 평가는 Live 중심입니다. 모든 카메라·모드·접근성 조합의 사용성 검증으로 일반화하지 않습니다.

CLI 전체 기능과 이전 실기기 계약 검증은 [CLI 후속 검증](cli-followup-20261009.md)을 확인하세요.

# App Bokeh 실기기 검증

2026-10-24에 SM-S936N, Android 16(API 36), 후면 카메라 ID 0에서 확인했다. 제조사 Bokeh와 센서 DEPTH16 없이 사물 사진에 배경 흐림을 적용하고 원본을 보존하는 경로를 검증했다. 사진과 화면 캡처는 로컬 검증 자료로만 보관하며 저장소와 PR에 올리지 않는다.

## 실기기 결과

| 시나리오 | 관찰 결과 |
| --- | --- |
| Depth → App Bokeh 진입 | 일반 Camera2 Preview 1280×720 + JPEG 1920×1080을 구성했다. 카메라 서비스 덤프의 출력은 PRIVATE와 BLOB 두 개이며 분석 YUV·DEPTH16·입력 스트림이 없었다. |
| 사물 촬영 | 가까운 마우스·책상과 먼 문·수납장이 보이는 장면을 촬영했다. 원본 JPEG 저장 후 편집기가 열렸다. |
| 동일 원본 비교 | 처리용 원본은 EXIF 방향 보정 후 900×1600이었다. 강도 50·100에서 배경 경계와 무늬가 단계적으로 흐려지고 마우스와 가까운 책상은 선명하게 남았다. |
| 깊이·기준면 | 256×256 상대 역깊이 맵에서 책상과 먼 배경이 구분됐다. 먼 배경을 선택하면 추가 흐림이 줄었다. |
| 강도 0 | 실기기 검사에서 처리용 원본과 `Bitmap.sameAs`가 참이었다. JPEG 재인코딩의 무손실을 뜻하지 않는다. |
| 저장 | UI의 Save copy로 Bokeh JPEG·깊이 PNG·JSON을 저장했다. JSON에서 원본 URI, 강도 100, 선택 좌표, 모델 해시, 900×1600 크기를 확인했다. 원본 파일은 유지됐다. |
| 반복 처리 검사 | 같은 원본에 강도 50·80·100을 적용하고 저장한 이미지들을 다시 디코딩했다. `APP_BOKEH_OK`를 받았다. |
| 화면 복귀 | Home 후 Live 복귀 시 같은 원본으로 편집기를 다시 열었다. 매개변수는 기본값으로 돌아갔다. 닫기 후 Photo 전환 시 일반 셔터와 YUV 포함 기본 세션으로 복귀했다. |
| 카메라 변경 | App Bokeh에서 후면 카메라 ID 2로 바꾸면 Photo가 선택되고 일반 셔터·기본 스트림으로 복귀했다. |
| 처리 시간 | 사진 로드·방향 보정·축소·깊이 추론을 합친 관찰값은 332, 533, 541 ms였다. 렌더·JPEG 저장 시간을 포함하지 않으며 성능 보장값이 아니다. |

## 자동 검사와 리뷰

순수 Kotlin 검사에서는 상대 깊이 정규화, 잘못된·평탄한 출력 거절, 전경 보존과 배경 흐림, 전경 색 번짐 억제, 강도 0, 기준면 변경, 일정한 색과 폭 1 이미지를 다룬다. 전체 `testDebugUnitTest`와 `lintDebug`, 앱·검사 APK 빌드를 별도로 실행했다. 기기 검사는 JVM 검사와 구분한다.

코드 리뷰에서 카메라 변경 후 App Bokeh 상태가 남는 경로를 발견해 다른 전용 모드와 함께 해제하도록 수정했다. 모드 종료 시 이전 App Bokeh 안내도 지운다. UI에서 Original 버튼이 줄바꿈되던 문제도 수정했다.

## 확인 범위와 한계

이번 새 장면은 후면 사물 한 장이다. 다른 기기·전면·인물·역광·반사체·얇은 경계의 품질을 검증한 것으로 해석하지 않는다. 마우스 주변과 가까운 책상은 보존됐지만 책상 뒤쪽 경계처럼 깊이가 바뀌는 곳에는 흐림이 번지는 부분이 있다. 단안 추정과 저해상도 깊이 맵의 한계이며, 정밀한 피사체 마스크나 광학 보케와 같지 않다. 최대 출력 긴 변은 1600픽셀이며 실시간 미리보기 효과는 제공하지 않는다.

처리·모델·스트림 계약은 [App Bokeh 설계](../design/APP-BOKEH.md)에 있다.

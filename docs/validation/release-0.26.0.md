# 0.26.0 구조·문서·기기 검증

**Multi의 선택 규칙과 화면 책임을 분리하고, 정식 0.26.0(versionCode 672)에서 버튼 조작을 재검증했습니다.** Galaxy S25+ SM-S936N · Android 16에 기존 앱을 삭제하지 않고 설치했습니다.

## 구조 검토와 수정

| 발견한 문제 | 수정 | 확인 |
| --- | --- | --- |
| Activity가 설정창과 카메라 선택 규칙을 함께 처리했습니다. | 순수 Kotlin `SplitSelection`과 UI `SplitChoiceSheet`로 분리했습니다. | 초안 격리, 장치 교환, 지원 조합 제한, 카메라 수 변경을 JVM에서 검사했습니다. |
| Multi 세션에 사용하지 않는 Physical·Service PIP 입력과 합성 사진 경로가 남았습니다. | 독립 장치 경로로 줄이고 조회는 `ConcurrentDiscovery`로 옮겼습니다. | 기기에서 각 장치의 원본 JPEG와 별도 MP4를 확인했습니다. |
| 화면과 설정창의 버튼 구성이 중복됐습니다. | `CameraWidgets.chromeButton`을 재사용합니다. | lint와 기존 UI 조작 검사가 통과했습니다. |
| 안내 문자열에서 성공·실패를 추정했습니다. | 저장 경계의 `ConcurrentMediaResult`로 상태를 전달합니다. | 사진 묶음은 실제 저장 상태, 영상은 장치별 결과로 실패를 결정합니다. |

상태 기계·장치 종료·버퍼 수명은 기존 구현을 유지했습니다. 인터페이스를 형식적으로 늘리지 않았으며 이 검토를 앱 전체의 SOLID 준수 인증으로 해석하지 않습니다.

## 기기 결과

정식 APK에서 `MultiSplitChecks`를 다시 실행했습니다. Split 취소·Apply·배치·카메라 조합·순서, Manual 제외, AF·AE·EV·Torch·줌, 터치 초점·핀치, Callback ID·Hold, Gallery·Lab 복귀, ZIP·공유 선택창과 네 모드 전환이 통과했습니다. Retry는 테스트에서 실패를 주입했습니다. 공유 대상에게 전송하지 않았습니다.

카메라 0·1의 JPEG는 각각 1920×1440이며 이미지와 결과의 센서 시각이 일치했습니다. MP4는 각각 720×1280, 무음이고 독립 재생이 가능했습니다. 녹화 중 원본 사진을 저장해도 두 녹화는 계속됐습니다. 항목별 절차는 [Multi 상세 기록](multi-split-20261012.md)에 모으며 여기서 반복하지 않습니다.

## 문서 검토

시작 페이지·Live·Callback·Glossary·엔진 비교·검증 목록과 현재 상태를 대조했습니다. 중복된 저장 설명은 Live로 연결하고, “Multi에는 Callback이 없다”와 “Multi 안에서 PIP를 쓴다”는 낡은 설명을 수정했습니다. 과거 검증 기록은 당시 조건을 보존합니다.

한 절차는 네 단계로 줄였고 첫 행동과 확인할 결과를 함께 적었습니다. 세부 조건은 펼침 영역으로 옮겼으며 제한 사항은 숨기지 않았습니다. 앞뒤를 한 번 찍고 배치를 바꿔 보는 실험을 넣어 읽은 내용을 바로 확인할 수 있게 했습니다. 실제 브라우저에서 Multi 절차·표·펼침 영역의 표시도 확인했습니다. 이는 집필 규칙과 화면 검토에 따른 개선이며 ADHD 독자를 대상으로 한 사용자 평가를 실시한 것은 아닙니다.

## 자동 검사

app JVM 테스트 814개와 `lintDebug`, `assembleRelease`, release 기기 테스트 APK 빌드가 통과했습니다. 문서 파이프라인 회귀 검사 33개가 통과했습니다. 문서 생성·담당 요소·사이트 빌드 6단계와 내부 링크 검사도 통과했습니다.

다른 제조사, 세 카메라 이상과 장시간 녹화는 별도 기기 검증이 필요합니다.

배포 APK의 패키지·버전·minSdk 26·targetSdk 36·비디버그 설정과 v2 서명을 확인했습니다. 인증서 SHA-256은 `f2432413635645cc35e674e498e88ff518abb878065c21f17bb3c2128487b5c1`로 기존 정식 릴리스와 일치합니다. 첨부 파일의 SHA-256은 릴리스의 `SHA256SUMS.txt`에 제공합니다.

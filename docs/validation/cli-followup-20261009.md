# CLI 사용 흐름과 추가 기기 검증 — 2026-10-09

Python CLI의 기본 출력을 짧은 상태·저장 위치·다음 행동으로 바꾸고 Galaxy S25+에서 오디오 녹화, 추가 CTS와 촬영 조합을 검증했습니다. 기존 CLI 확장 검증은 [이전 기록](cli-parity-20261009.md)에 있습니다.

## 사용 흐름 개선

1. 인자 없이 `halcam`을 실행하면 시작 작업 다섯 개를 보여 줍니다. 기기 연결 없이 도움말을 읽을 수 있습니다.
2. 기본 출력은 성공·실패, 요청 ID와 저장 위치를 표시합니다. `--json`은 전체 응답 계약을 유지합니다. 결과 목록은 항목을 임의로 생략하지 않습니다.
3. 대기 중 상태나 저장 장수가 바뀔 때만 진행을 알립니다. 완료 후에는 이전의 `capturing` 단계를 진행 중인 것처럼 표시하지 않습니다.
4. 실패 후에는 현재 기기 선택과 ADB 설정을 유지한 다음 명령 하나를 제공합니다. 취소 후 저장 파일이 있으면 회수를 먼저 안내하고, 대기 시간 초과에는 같은 요청의 상태를 확인하게 합니다.
5. 녹화 시작·정지 접수·최종 저장을 구분합니다. Python의 `run record.start --no-audio`는 무음 녹화를 요청합니다.

실기기 검토에서 제출 전 BUSY 오류가 아직 존재하지 않는 요청 ID를 안내하던 문제를 발견했습니다. 새 ID는 접수 확인 후 표시하고, 앱이 명확하게 거부한 요청에도 잘못된 ID를 붙이지 않습니다. 전송 중 통신이 끊긴 경우에는 접수 여부가 불확실하므로 상태 확인에 필요한 ID를 유지합니다.

이는 인지 부담을 줄이기 위한 구현·검토이며 ADHD 사용자를 모집한 사용성 연구 결과는 아닙니다.

## 기기와 방법

자동 검사는 Python·셸 회귀 테스트 69개와 문서 회귀 테스트 33개가 통과했습니다. 이번 변경은 Android 코드를 수정하지 않으며, 이전 JVM 테스트 수를 이번에 재실행한 결과로 표시하지 않습니다. 코드·문서 대조 검토는 사용자 요청으로 Codex가 수행했습니다.

- Galaxy S25+ (SM-S936N), Android 16/API 36, 기존 동일 서명 검증 빌드 658을 사용했습니다.
- 앱 코드는 PR #254와 같고, 이번 변경은 PC Python CLI와 문서입니다. 앱 삭제·데이터 초기화·재설치는 하지 않았습니다.
- 원본 사진·동영상은 PC에 보관하고 저장소에 올리지 않습니다. 파일 회수 시 크기와 SHA-256을 검사했습니다.
- 초기 화면이 꺼진 상태의 직접 호출은 APP_NOT_FOREGROUND로 거부됐습니다. 화면을 깨우고 CLI 진입 화면을 연 뒤 검증했습니다.

검증 전후 기존 실행 목록과 baseline 표시를 동일하게 유지했음을 대조했습니다. 종료 시 프리뷰를 정지했습니다. 모든 제조사·카메라·출력 조합이나 전체 vendored CTS를 검사한 결과는 아닙니다.

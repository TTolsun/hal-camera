# Dual 프레임별 Callback과 CameraX Video 준비 실패 검증

2026-11-27에 Galaxy S25+ (SM-S936N, Android 17)를 무선 ADB로 연결했습니다. Depth/Bokeh 제거 커밋 `14139860`을 기반으로 수정한 디버그 APK를 별도 패키지에 설치하고, `callback_frames` 기기 검사를 세 차례 실행했습니다. 세 실행이 모두 통과했습니다.

| 검사 | 기기에서 확인한 결과 |
| --- | --- |
| Camera2 Dual, Hold 0초 | 촬영 전에는 두 Preview 행이 보였습니다. 셔터를 누르자 사진 프레임에 두 photo 행이 표시됐고, 이후 더 큰 프레임 번호와 두 Preview 행이 돌아왔습니다. |
| Camera2 Dual, Hold 5초 | 프리뷰 세션에서 다음 Shutter가 들어온 후에도 그래프는 촬영한 프레임 번호를 유지했습니다. 두 photo 행에 각각 도착값이 표시됐습니다. 만료 직전에도 같은 사진 프레임이었고, 만료 후에는 두 Preview 행이 표시됐습니다. |
| CameraX Video 준비 실패 | 기본 Preview·YUV·JPEG를 바인딩한 뒤 고정 코덱 H264를 지정해 CameraX의 Auto 코덱 검증에서 실패시켰습니다. 오류 이벤트와 함께 기본 출력 세 행이 표시됐고 YUV 행에 실제 도착값이 기록됐습니다. Recording 행은 생기지 않았습니다. |

검사는 `CliStoreInstrumentation`에서 `-e callback_frames true`로 실행합니다. 물리 카메라 두 개로 동시에 YUV 사진을 찍을 수 있는 기기가 필요합니다. 한 번 실행하면 Hold 설정별로 사진을 두 장씩 저장하고 원래 Hold 설정을 복구합니다. CameraX 검증은 영상 유스케이스를 바인딩하기 전의 준비 실패 경로를 대상으로 합니다.

## CameraX Dual의 GL 입력과 물리 결과

2026-11-27에 같은 Galaxy S25+에서 메인 ID 5와 서브 ID 6을 선택하고 `CliStoreInstrumentation`의 `-e dual_gl true` 검사를 두 번 연속 실행했습니다. 사진 프리뷰, 영상 프리뷰, 실제 녹화를 순서대로 검사했습니다. 녹화할 때는 무음 MP4 두 개가 생성됩니다.

| 두 실행의 합계 | 메인 GL 입력 중 물리 결과와 일치 | 서브 GL 입력 중 물리 결과와 일치 | 대조한 화면 프레임 | 메인 행에 값이 표시된 프레임 | 서브 행에 값이 표시된 프레임 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 사진 프리뷰 | 105 / 191 | 159 / 192 | 42 | 30 | 42 |
| 영상 프리뷰 | 113 / 190 | 174 / 190 | 43 | 35 | 43 |
| 녹화 중 | 110 / 194 | 179 / 194 | 41 | 34 | 41 |

수신한 GL 입력은 모두 1,151개였습니다. 각 입력에 기록한 물리 ID와 버퍼 타임스탬프를 촬영 결과와 대조하니 840개가 해당 물리 카메라 결과와 일치했습니다. 나머지 311개는 논리 결과의 타임스탬프와만 일치했습니다. 정확히 일치하는 비율은 같은 기기에서도 실행에 따라 달라졌습니다.

화면은 모든 GL 입력을 차례대로 표시하지 않으므로, 화면 검사는 별도로 진행했습니다. 검사 시점에 그래프가 표시한 프레임 번호를 읽고 해당 프레임의 물리 결과, 셔터 기준 시각, GL 입력 이벤트로 두 행의 값을 각각 다시 계산했습니다. 126개 프레임의 252개 행 중 225개에는 계산과 같은 값이 표시됐고, 대응하는 입력이 없는 27개 행에는 `Awaiting data`가 표시됐습니다. 세 시나리오 모두 메인과 서브 행이 유지됐습니다.

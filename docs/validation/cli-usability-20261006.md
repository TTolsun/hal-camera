# adb 전용 CLI 사용성 조사

PC에 adb만 설치되어 있어도 현재 CLI를 사용할 수 있습니다. 명령 해석과 완료 대기는 APK에 포함된 Android 셸 스크립트가 처리하므로 Python·pip·Git·JDK는 사용자 측 필수 조건이 아닙니다. 다만 앱의 모든 기능이 CLI에 노출되어 있지는 않으며, 연결 선택·초기 진단·스크립트 갱신·결과 회수에는 사용자가 수행할 단계가 남아 있습니다.

## 조사 기준

- 2026-10-06에 `main`의 `b05c089`를 기준으로 조사했습니다. 다른 worktree에서 개발 중인 기능은 포함하지 않았습니다.
- 계약과 명령 범위는 `CliCommand.kt`, `AdbArguments.kt`, `CliStreams.kt`, `CommandCoordinator.kt`, `LiveController.kt`, `halcam.sh` 및 `guide/cli.md`를 대조했습니다.
- 앱 기능은 `MainActivity.kt`, `camera/CameraEngine.kt`, `camera/LiveControls.kt`, `WorkbenchActivity.kt`와 대조했습니다.
- 아래 개선은 셸 클라이언트와 문서에 한정됩니다. 새 카메라 제어 프로토콜은 추가하지 않았습니다.

## 기능 범위

| 기능 | adb 전용 CLI | 확인 결과 |
| --- | --- | --- |
| 카메라·스트림 지원 조회 | 지원합니다. | `cameras`, `streams`를 사용합니다. 물리 endpoint는 조회되지만 단독 카메라로 선택하지 못합니다. |
| 프리뷰·정지·사진 | 지원합니다. | Camera2·CameraX, 프리뷰/YUV/JPEG 크기와 출력 끄기를 지정할 수 있습니다. |
| 녹화 시작·정지 | 지원합니다. | 크기·FPS·코덱·마이크 여부를 지정하고 MP4 저장 완료를 기다립니다. |
| Probe·CTS | 지원합니다. | 사양 JSON/TXT, CTS 목록과 선택 실행 및 결과 회수를 지원합니다. |
| 상태·취소·파일 재회수 | 지원합니다. | 요청 ID 기반 복구가 가능하며 새 촬영을 실행할 필요가 없습니다. |
| 줌·EV·AE/AF 잠금·플래시 | CLI에 없습니다. | 앱의 Live 제어에는 있지만 명령 인자에 없습니다. CLI 준비 과정에서 줌과 Live 제어는 초기화됩니다. |
| 터치 초점·측광 | CLI에 없습니다. | 앱은 프리뷰 좌표를 사용합니다. 자동화용 좌표계와 변환 규칙이 필요합니다. |
| 녹화 중 사진 | CLI에 없습니다. | 앱에는 snapshot 동작이 있으나 CLI는 진행 중 녹화의 정지·취소만 받습니다. 별도 제어 계약과 결과 귀속이 필요합니다. |
| 벤치마크 | 조사 기준 커밋에서는 제외되어 있었습니다. | 후속 요청으로 `benchmark run`을 추가했습니다. 현재 계약은 CLI 가이드를 확인합니다. |
| 기존 갤러리·ZIP 기록 관리 | CLI에 없습니다. | `fetch`는 해당 CLI 요청의 산출물에 한정되며 앱 저장 자료 전체의 브라우저가 아닙니다. |

수동 ISO·노출 시간·초점 거리·안정화 제어는 이 기준 커밋에서 사용자 제어 기능으로 확인되지 않았습니다. 따라서 이미 지원하는 앱 기능의 CLI 누락으로 분류하지 않습니다. 선택 도구인 Python 클라이언트에는 녹화와 프리뷰 정지가 없으므로 기본 사용 경로는 adb 셸 스크립트로 통일하는 편이 명확합니다.

## 초기 사용 과정과 이번 개선

| 단계 | 발견한 불편 | 반영 내용 또는 남은 조건 |
| --- | --- | --- |
| adb 실행·연결 | PATH, `unauthorized`, `offline`, 다중 연결을 처음 접하면 원인을 구분하기 어렵습니다. | 가이드 앞부분에 연결 확인과 대응 절차를 추가했습니다. 앱 내부 스크립트는 adb 연결 자체를 진단할 수 없습니다. |
| 앱 준비 | CLI 허용·카메라 권한·잠금 상태를 JSON으로 직접 해석해야 했습니다. | `doctor`를 추가했습니다. 부족한 조건과 다음 조치를 출력하고 실패 종료 코드를 반환합니다. |
| 스크립트 설치·갱신 | APK 갱신만으로 `/data/local/tmp/halcam`이 갱신되지 않습니다. | 갱신 절차를 명시했습니다. 자동 버전 대조·갱신은 아직 없습니다. |
| 현재 작업 확인 | `status`가 마지막 요청을 기억하므로 현재 앱 상태를 보기 어려웠습니다. | `status --app`을 추가했습니다. 오래된 요청 기록을 건드리지 않고 현재 상태를 읽습니다. |
| 오류 이해 | 오류 JSON만 출력하며 일부 문서의 설정 경로와 disabled 응답 설명도 낡았습니다. | 주요 오류의 조치 안내와 `Lab → ADB CLI` 경로를 보완했습니다. disabled 응답은 `enabled: false`가 아닌 `CLI_DISABLED`입니다. |
| 작업 성공 판정 | 취소된 완료 요청에 오류 객체가 없으면 성공 문구가 나올 수 있었습니다. | `state: succeeded`일 때만 성공으로 처리하고, 나머지는 비정상 종료와 파일 회수 방법을 안내합니다. |
| 파일 회수 | 출력된 `adb pull`에 기기 선택이 없어 다중 연결에서 실패합니다. | 같은 `-s SERIAL`을 붙이라는 안내를 출력합니다. 기기 스크립트는 PC가 선택한 ADB 연결 문자열을 알지 못하므로 자동 삽입하지 않습니다. |

`doctor`는 마이크·저장소 권한이나 출력 조합의 성공을 완전히 검증하지 않습니다. 이를 성공 문구와 가이드에 명시했습니다. CLI 허용은 사용자가 앱에서 켜야 하고, 진단은 이 동의 절차를 우회하지 않습니다.

## 검증 결과

1. Codex에 포함된 Python 런타임으로 `PYTHONPATH=tools/halcam`을 설정하여 CLI 테스트 44개를 실행했고 모두 통과했습니다. 그중 셸 클라이언트 테스트는 19개이며 정상 진단, 권한·잠금·BUSY, CLI disabled, 현재 앱 상태 조회, 오류 없는 취소를 포함합니다. 이 Python은 개발 검증용이며 CLI 사용자에게 요구하지 않습니다.
2. Galaxy S25+ (`SM-S936N`), Android 16, 설치된 HAL CAM 0.19.0에서 수정 스크립트를 별도 경로 `/data/local/tmp/halcam-usability-review`에 올려 `doctor`와 `status --app`을 실행했습니다. CLI 허용·카메라 권한·잠금 해제·Live foreground·busy=false를 읽었고 두 명령 모두 정상 종료했습니다.
3. PC의 ADB 목록에는 같은 모델의 무선 IP 연결과 mDNS 연결이 함께 있었습니다. 명령에는 IP 연결을 명시했습니다. APK 교체·앱 삭제·촬영·녹화·권한 변경은 수행하지 않았습니다. 실패 조건은 가짜 transport 테스트로 검증했으며 실기기 권한을 변경해 재현하지는 않았습니다.
4. `node tools/docgen/docflow.mjs check --build`의 6단계와 `site check`를 통과했습니다. APK에 새 스크립트를 포함하는 재빌드 및 배포는 이번 검증 범위에 포함하지 않았습니다.

## 후속 개선 우선순위

1. **카메라 제어 범위를 먼저 확정합니다.** 줌·EV·잠금·플래시의 지원 범위 조회, 요청값/실제 적용값, 실패 규칙을 설계한 뒤 CLI 인자를 추가합니다. 녹화 중 snapshot은 진행 중 요청을 유지하면서 별도 산출물을 연결하는 계약이 필요합니다.
2. **명령 길이와 연결 선택을 줄입니다.** 선택형 PC 래퍼를 제공한다면 Windows PowerShell·CMD와 POSIX 셸에서 adb 경로·serial·출력 디렉터리를 일관되게 처리해야 합니다. 필수 추가 런타임을 도입하지 않는 것이 목표입니다.
3. **셸 버전과 선택 권한의 진단을 확장합니다.** `hello`에 셸 버전 및 마이크·저장소 준비 상태를 추가하면 오래된 스크립트를 감지하고 녹화·저장 실패를 더 일찍 안내할 수 있습니다.

실행 절차는 [CLI 가이드](../../guide/cli.md)를 확인하세요.

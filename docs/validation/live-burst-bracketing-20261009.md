# Live 연사와 노출 브라케팅 검증

Live에서 셔터를 길게 누르는 연사(#244)와 AEB 노출 브라케팅(#247)을 실기기에서 검증했습니다. #178의 자동 EV 방식 범위입니다. 수동 센서 방식 브라케팅은 포함하지 않습니다.

## 환경

- 기기는 Samsung Galaxy S25+(Android 16)이며 후면 기본 카메라를 사용했습니다. 시험은 Camera2와 CameraX 두 엔진에서 모두 진행했습니다.
- 기존 앱을 삭제하지 않고, 같은 인증서로 서명한 release APK를 `install -r`로 덮어 설치했습니다.
- 조작은 무선 adb의 화면 입력으로 했습니다. 결과는 저장된 파일 이름과 촬영 JSON의 노출 시간·ISO·`evApplied`로 확인했습니다.

## 결과

| 검사 | 결과 |
| --- | --- |
| JVM·빌드·lint | testDebugUnitTest와 lintDebug가 통과했습니다(663개, 실패 0). `BurstRun`의 순차 촬영, 바쁜 엔진 대기, 연속 2회 실패 시 중단, 취소 후 진행 중인 촬영 보고, prepare 중 취소를 검사합니다. `BracketPlan`의 EV 단계와 범위 제한, AEB를 끄는 조건도 검사합니다. |
| 연사 · Camera2 | 3초 동안 누르면 6~7장, 다시 시험했을 때 5장이 저장되었습니다. 촬영 시작 간격은 약 376~501 ms였습니다. 손을 떼면 다음 장을 찍지 않고 멈췄습니다. |
| 연사 · CameraX | 3초 동안 누르면 3장이 저장되었고 간격은 약 1.1~1.25 s였습니다. 손을 떼면 멈췄습니다. |
| 짧은 누름·탭 | 길게 누르기로 인식될 만큼만 누르면 1장, 탭하면 일반 사진 1장이 저장되었습니다. |
| 브라케팅 · Camera2(밝은 장면) | 탭 한 번에 3장을 저장했습니다. ev+0.0은 16.7 ms·ISO 274, ev-2.0은 8.3 ms·ISO 69(약 −3.0 EV), ev+2.0은 33.3 ms·ISO 410(약 +1.6 EV)였습니다. |
| 브라케팅 · CameraX(밝은 장면) | ev+0.0은 8.3 ms·ISO 317, ev-2.0은 8.3 ms·ISO 70(약 −2.2 EV), ev+2.0은 33.3 ms·ISO 308(약 +2.0 EV)였습니다. JSON의 `evApplied`는 0, −20, +20이었습니다. |
| 브라케팅 · 어두운 실내 | Camera2에서 ev-2.0은 약 −2 EV였으나 ev+2.0은 약 +0.6 EV에 그쳤습니다. 노출 시간과 ISO가 상한에 가까워 더 밝게 찍을 수 없었습니다. |
| EV 복귀 | 두 엔진 모두 브라케팅이 끝난 뒤 EV가 0으로 돌아왔습니다. |
| AEB 버튼 | 상단 제어 줄의 버튼 6개(플래시·AF·AE·EV·AEB·M)가 한 줄에 들어갔습니다. AEB를 켜고 끌 때 안내가 표시되었고, AEB를 끄면 탭 한 번에 1장이 저장되었습니다. |

노출 차이는 기준 사진(ev+0.0)과의 노출 시간×ISO 비로 계산했습니다. 장마다 AE가 다시 수렴하는 동안 장면 밝기가 바뀌면 그 영향이 함께 들어갑니다. 따라서 요청한 EV는 `evApplied`로, 실제 노출은 노출 시간과 ISO로 구분해서 읽습니다.

휴대폰을 손에 든 상태에서 진행한 시험 두 번은 결과에서 제외했습니다. 화면 터치가 길게 누르기 입력과 겹쳤기 때문입니다. 휴대폰을 내려놓고 다시 시험했을 때 두 결과는 재현되지 않았습니다.

## 검증 범위

- 각 장의 EV를 적용한 뒤 고정 500 ms를 기다리고 촬영합니다. AE가 실제로 수렴했는지는 확인하지 않습니다.
- 수동 노출(M) 중에는 AEB를 켤 수 없습니다. ISO·셔터를 바꾸는 수동 센서 방식 브라케팅은 구현하지 않았습니다.
- 다음 상황은 단위 테스트로만 확인했고 실기기에서 측정하지 않았습니다.
  - 촬영 중 카메라 전환·화면 종료
  - 저장 공간 부족
  - 일부 장 실패
- Android 8~9의 권한 대화상자가 길게 누르기를 취소하는 경우는 코드로 막았지만 해당 버전 기기에서 확인하지 않았습니다.
- 브라케팅 묶음의 HDR 합성은 #242에서 다룹니다.

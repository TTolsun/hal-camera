# 0.30.0 검증

**Galaxy S25+ (SM-S936N), Android 16에서 Camera2·CameraX Multi CLI의 프리뷰·사진·유음 및 무음 녹화와 파일 회수를 확인했습니다.** 2026-10-19 정식 서명 APK 0.30.0 (versionCode 691)을 기존 앱 위에 설치했습니다. 앱 삭제나 데이터 초기화는 하지 않았습니다.

## 자동 검사

- `assembleRelease`, `testDebugUnitTest`, `lintDebug`, `assembleDebugAndroidTest`가 통과했습니다. 앱 JVM 테스트는 897개이며 lint는 오류·경고 없이 끝났습니다.
- Python 3.14에서 CLI 테스트 111개와 집계 도구 테스트 10개가 통과했습니다. CLI 테스트에는 APK의 POSIX shell 클라이언트를 Git Bash에서 실행하는 검사도 포함합니다.
- 문서 회귀 검사 37개가 통과했습니다. 새 Multi CLI 요소를 분리하여 모든 구조 근거가 문서 엔진의 60,000자 입력 한도 안에 들어갑니다.
- 순수 Kotlin 검사에서 조합·크기·목록의 엄격한 거부, 역순 콜백의 카메라 소유권, 일부 사진 성공 보존, 준비 중 취소·정지와 화면 전환의 닫기 순서를 확인했습니다.

## 기기에서 실행한 조합

`multi cameras`는 {0,1}, {0,3}을 advertised 조합으로 반환했습니다. 아래 명령에서는 전면 카메라를 먼저 지정하여 요청 순서도 확인했습니다.

| 엔진 | `--cameras` | 프리뷰·현재 화면 정보·정지 | 사진 | 무음 영상 | 유음 영상 |
| --- | --- | --- | ---: | ---: | ---: |
| Camera2 | `1,0` | 통과 | 2장 | 2개 | 2개 |
| Camera2 | `3,0` | 통과 | 2장 | 2개 | 2개 |
| CameraX | `1,0` | 통과 | 2장 | 2개 | 2개 |
| CameraX | `3,0` | 통과 | 2장 | 2개 | 2개 |

기본 프리뷰는 1280×720, 사진은 1920×1440으로 요청했습니다. 녹화 시작 완료 후 약 2초를 기다렸다가 `record stop`으로 저장했습니다. 사진 8장과 영상 16개 모두 PC 회수 시 크기·SHA-256 검사를 통과했고, FFmpeg 전체 디코딩도 통과했습니다. 무음 MP4에는 영상 트랙만, 유음 MP4에는 영상과 오디오 트랙이 있었습니다. 카메라별 결과와 회수 이름의 ID가 요청 순서와 일치했습니다.

초기 CameraX 프리뷰 뒤 촬영에서 준비 시간 초과를 재현했습니다. Dual·Multi에서 Live로 돌아갈 때 이전 카메라의 닫기 완료를 기다리도록 수정한 뒤 CameraX의 두 조합을 연속 프리뷰→정보→사진→무음 녹화→유음 녹화→정지 순서로 다시 실행하여 통과했습니다.

Camera2의 `--cameras 1,0 --preview-sizes 640x480,1280x720 --photo-sizes 1280x720,1920x1440` 요청도 성공했습니다. 회수한 1번 JPEG는 1280×720, 0번 JPEG는 1920×1440으로, 카메라 순서별 크기 지정이 실제 파일에 유지됐습니다.

## 오류와 종료 경로

- 광고되지 않은 `0,2`, 목록 밖 크기 `800x600`, CameraX의 `0,1,3` 요청은 `PREFLIGHT_FAILED`, 중복 `0,0`은 `INVALID_ARGUMENT`로 거부했습니다.
- `--no-wait`로 접수한 직후 정지한 Live 녹화와 Camera2·CameraX Multi 녹화가 모두 저장을 마쳤습니다. 준비 중 정지 의도가 화면 인계 뒤에도 유지됐으며, 완료 후 busy 상태가 해제됐습니다.
- 현재 Multi 화면에서 `events`가 ZIP을 저장했습니다. Events 취소는 `cancelled`로 끝났고 ZIP 1개를 보존했습니다. 녹화 취소도 `cancelled`와 영상 2개를 보존했습니다.
- 녹화 중 홈으로 나가면 `APP_NOT_FOREGROUND`로 끝나고 busy 상태가 해제됐습니다.
- 마이크 권한을 잠시 해제했을 때 유음 요청은 `PERMISSION_REQUIRED`로 거부됐으며, 같은 상태의 `--no-audio` 녹화는 저장까지 성공했습니다. 검사 뒤 마이크 권한을 원래 허용 상태로 복구했습니다.

## 검증하지 않은 범위

실제 센서·저장 오류를 인위적으로 주입한 일부 사진 실패는 기기에서 실행하지 않았으며, 일부 성공 보존은 순수 Kotlin 결과 집계 검사로 확인했습니다. Android 10 이하와 다른 OEM은 이번 기기 검사에 포함하지 않았습니다. 장시간 녹화·열 부하·센서 동기·박수를 이용한 영상 및 소리 동기 측정도 수행하지 않았습니다. Multi의 카메라별 제어·측광·녹화 중 사진·CLI 배치는 후속 범위입니다.

코드 리뷰의 수정 근거는 [CLI PR 리뷰](cli-review-20261019.md), 사용자 변경 내용은 [0.30.0 릴리스 기록](../releases/0.30.0.md)을 확인하세요.

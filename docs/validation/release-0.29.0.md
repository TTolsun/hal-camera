# 0.29.0 CameraX Multi·오디오 검증

2026-10-17 Galaxy S25+ (SM-S936N), Android 16에서 정식 서명 release APK를 기존 앱 위에 `adb install -r`로 설치했습니다. 앱 삭제나 데이터 초기화 없이 `dev.halcamera` 하나를 유지했습니다.

## 코드 검증

- JVM 테스트 832개가 통과했습니다. 오디오 시작 시각 차이, preroll 제거, 영상 끝 이후의 오디오 제외, 카메라별 독립 시각 정렬을 포함합니다.
- `assembleRelease`, `testDebugUnitTest`, `lintDebug`가 통과했습니다. lint 오류 0개·경고 131개입니다.
- 화면은 MultiSession 계약을 사용하고 엔진별 장치 제어를 분리했습니다. 사진 저장소와 녹화·오디오 처리를 재사용하며 미사용 녹화 상태 접근자를 제거했습니다.
- CameraX 구성 실패 시에도 CLOSED 관찰자를 먼저 등록하여 종료 완료를 기다리게 했습니다. 터치 측광은 프리뷰 회전·전면 반사를 센서 좌표로 역변환합니다.

## 기기 검증

| 시나리오 | 결과 |
| --- | --- |
| Camera2 Multi V | 두 개의 H.264 MP4에 48kHz AAC가 포함됐습니다. 약 10.3초 영상에서 실제 오디오 신호를 확인했습니다. |
| CameraX Multi V | 전·후면 동시 프리뷰와 독립 MP4 저장에 성공했습니다. 약 8.2초 녹화 및 최종 APK의 약 5.2초 재검증에서 두 파일 모두 AAC와 실제 신호를 확인했습니다. |
| CameraX Multi P | 카메라 0·1의 원본 JPEG 두 개와 갤러리 썸네일을 확인했습니다. |
| P/V·엔진 전환 | Camera2에서 CameraX로 전환하고 CameraX V→P→V를 반복해 두 프리뷰가 다시 준비됐습니다. |
| 카메라 ID 이동 | CameraX에서 전·후면 패널을 바꾸면 각 카메라의 FPS/EXP도 함께 이동했습니다. |
| 갤러리 영상 재생 | CameraX 영상의 프레임 진행과 Android 오디오 플레이어의 48kHz 재생 시작을 확인했습니다. 사람이 스피커 소리를 청취한 검증은 아닙니다. |

PC에서 FFprobe로 스트림을 조사하고 FFmpeg로 각 파일 전체를 디코딩했습니다. 최종 CameraX 파일 두 개의 오디오 평균은 -44.5dB, 최대는 -30.0dB로 무음 데이터가 아니었습니다. MediaRecorder 시작 시각을 기준으로 오디오를 정렬하며 sample 단위 동기를 보장하지 않습니다. 짧은 시험 영상에서는 오디오 트랙이 영상보다 약 0.3초 짧았습니다.

## 한계

CameraX는 광고된 조합의 최대 두 카메라만 지원합니다. 요청한 크기를 구성하지 못하면 오류로 종료하며 자동 축소하지 않습니다. 같은 마이크 신호를 각 원본에 넣으므로 카메라마다 별도의 소리를 녹음하지는 않습니다.

프리뷰 FPS는 저장 영상 FPS를 보장하지 않습니다. 이번 짧은 녹화에서 저장 영상은 카메라별 약 18~24fps였으며, 30fps 성능 문제를 해결한 릴리스로 해석하면 안 됩니다. 다른 제조사, 장시간 녹화의 동기 오차, 저장 공간 부족·마이크 경쟁 등의 하드웨어 실패 주입은 검증하지 않았습니다.

사용 방법은 [Live 가이드](../../guide/live.md)를 참고하세요.

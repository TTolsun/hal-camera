## 수정한 문제

1. `record stop`이 준비·화면 인계 중 들어오면 현재 Live host가 정지를 소비하고 이후 녹화를 시작할 수 있었습니다. coordinator가 정지 의도를 보관하고 실제 `recordingStarted` 뒤 현재 host에 전달합니다.
2. 클라이언트가 Dual·Multi에서 Live를 열면 기존 화면의 비동기 종료보다 MainActivity의 카메라 열기가 앞설 수 있었습니다. CameraX Multi의 프리뷰 뒤 촬영에서 준비 제한 시간 초과를 재현했습니다. `CliNavigationHost.closeForNavigation` 완료 후에 Live를 열도록 변경했습니다.
3. 기존 Multi 영상 결과의 URI 목록은 카메라 ID를 전달하지 않아 콜백 순서로 파일 소유권을 추정할 수 없었습니다. 카메라 ID별 성공·실패 결과를 추가하여 요청 순서로 파일을 등록합니다. 기존 UI의 영상 묶음 롤백 규칙은 유지합니다.

순수 Kotlin 검사는 잘못된 조합·크기·목록, 준비 중 취소·정지, 닫기 완료 전 전환 금지, 역순 콜백과 일부 성공을 검증합니다. PC 검사는 명령·spec fixture, Multi 인자 순서, 현재 화면 유지와 파일 검증을 다룹니다.

실기기 결과와 검증하지 않은 범위는 [0.30.0 검증 기록](release-0.30.0.md)에 정리합니다.

# 내부 Camera Endpoint Score 초안

`score-v1-draft`는 동일 기기 모델·카메라 endpoint·측정 계약에서 성능 변화를 확인하는 내부 점수입니다. 여러 기기의 성능 순위를 나타내는 공개 점수는 아닙니다. 공개 버전 `score-v1`은 여러 제조사·성능군의 5–10개 기기 분포와 별도 검증이 필요합니다.

## 학습 데이터

정상 조명과 고정 장면에서 같은 기기 빌드·endpoint·`camera2-standard-v1`으로 측정한 서로 다른 run 10회 이상을 사용합니다. release 빌드 여부, 비충전, 배터리 20% 이상, 절전 해제, thermal 최고값 MODERATE 미만과 `scoring_eligible`을 확인합니다. 환경 정보가 누락된 측정은 학습에 넣지 않습니다.

`scoring_eligible=true`만으로 정상 조명이라고 판정하지 않습니다. 조명과 카메라 점유 경쟁은 별도로 확인하고, 저조도·발열·점유 경쟁 측정은 민감도 검증용으로 분리합니다. 2026-09-12 첫 10회는 사용자가 미리 조명을 낮췄다고 알려 주어 `uncertain-lighting`으로 분류했으며 학습에서 제외했습니다. 원본 JSON의 메모를 수정해 정상 조건으로 바꾸지 않습니다.

## 계산 규칙

`ScoreComposer.calibrate`는 지표별 정상 분포의 중앙값을 중심값으로 사용합니다. 척도는 다음 세 값 중 가장 큰 값입니다.

- 정렬된 n개 값의 인덱스 `floor(3(n−1)/4)`와 `floor((n−1)/4)` 사이의 차이입니다.
- 중앙값의 15%입니다.
- 지표별 고정 최소 척도입니다. 일정한 프레임 간격이나 실패 횟수 0의 분포에서도 0으로 나누지 않도록 합니다.

모든 포함 지표는 값이 낮을수록 좋습니다. `metric.value`를 사용하며 H.2의 p95나 H.10의 jitter를 p50으로 대체하지 않습니다.

```text
metric_score = clamp(800 − 200 × (value − center) / scale, 0, 1000)
category_score = 해당 카테고리 지표 점수의 산술평균
endpoint_score = round(LAUNCH, PREVIEW, CAPTURE, STABILITY 점수의 산술평균)
```

정상 중앙값을 800으로 두고 척도 하나의 저하를 200점으로 표현하는 것은 내부 초안의 설계 선택입니다. 이 숫자는 다기기 데이터로 검증한 품질 등급이나 확률이 아닙니다. 수식·지표 집합·가중치·계수 또는 학습 데이터가 변경되면 scoring rule 버전을 변경해야 합니다.

| 카테고리 | 포함 지표 | 최소 척도 |
|---|---|---|
| LAUNCH | 1.1, 1.3, 1.8, 1.6 | 10 ms |
| LAUNCH | 1.2, 1.7 | 5 ms |
| PREVIEW | H.1, H.2 | 2 ms |
| PREVIEW | H.3, H.4 | 5 ms |
| PREVIEW | H.10 | 1 ms |
| CAPTURE | 2.2, 2.3, 2.5 | 10 ms |
| STABILITY | H.5 | 2회 |
| STABILITY | H.9 | 1회 |

각 카테고리의 가중치는 25%이며 카테고리 안의 지표 가중치는 동일합니다. 3A의 가중치는 0입니다. 현재 profile에서 측정하지 않는 2.7과 RESOURCE·SWITCH도 포함하지 않습니다. 16개 필수 지표 중 하나라도 누락되거나 중복되거나 유효한 유한수가 아니면 전체 점수를 내지 않습니다. 누락된 지표를 0점이나 만점으로 대체하거나 남은 지표에 가중치를 재분배하지 않습니다.

## 사용 범위와 검증

검토한 S25+ 후면 메인 계수와 10회 측정값·해시는 [실측 근거](data/m5-s25-main-20260912.json)에 보관합니다. 사용자가 밝은 조명을 확인한 뒤 측정한 run만 포함하며, 이전의 조명 불명확 10회는 제외 목록에 기록했습니다. 저조도 3회는 계수 학습 후 별도로 평가했습니다. 정상 점수 중앙값은 805점, 저조도는 787점이지만 범위가 겹치므로 일관된 저하가 검증된 것은 아닙니다.

정상 점수 계산은 저장된 플래그를 현재 규칙으로 재평가하고 환경값도 확인합니다. 디버그·빌드 종류 불명·다른 모델·다른 endpoint·다른 측정 계약에는 해당 calibration을 적용하지 않습니다. 비교 기준이 없다는 `no_baseline`은 측정값이 존재하면 점수 계산을 막지 않습니다.

`ScoreComposer.sensitivity`는 측정 자체가 유효한 스트레스 run을 오프라인으로 평가하기 위한 별도 경로입니다. 결과를 정상 적격 run의 점수로 저장하지 않습니다. 중단·측정 실패에 임의의 0점을 부여하지 않고 계산 불가로 처리합니다.

단위 테스트는 데이터 수와 중복, 상수 분포, 성능 저하에 따른 단조성, 0–1000 범위, 카테고리 가중치, 3A 제외, 환경·계약 불일치, 누락·비유한수, 민감도 결과와 정상 점수의 분리를 검증합니다. 실제 스트레스 조건에서 점수가 감소하는지는 별도의 실기기 결과로 확인해야 합니다.

현재 실측과 남은 검증 상태는 [STATUS.md](STATUS.md)에 기록합니다.

카메라 콜백 하나가 화면 위의 숫자가 되기까지의 경로입니다. 파이프라인은 한 방향이고 각 단계마다 데이터가 좁혀지는데, 이 때문에 앱의 어떤 부분도 이미 기록된 결과를 다시 계산하지 않습니다.

흐름은 두 갈래로 나뉘었다가 실행 파일에서 다시 합쳐집니다. **이벤트 경로**는 프레임워크가 보고하는 모든 것을 기록하고 거기에서 관측 지표(H.x)를 뽑아냅니다. **러너 경로**는 각 API 호출 전후의 타임스탬프만 기록하고, 그 표시들을 짝지어 빼는 방식으로 실행 지연과 촬영 지연(1.x, 2.x)을 구합니다. 두 경로는 `CheckEvaluator`에서 만납니다. 러너는 관측 창이 언제 열리고 닫혔는지 알고, 이벤트는 그 안에서 무슨 일이 일어났는지 알기 때문에 둘 다 필요합니다.

평가 단계는 제품 세대에 따라 다시 갈라집니다. v0.2 경로는 임계값과 baseline에 견주어 판정하고 상태, 진단, 건강 수준을 만듭니다. v0.3 경로는 동일한 백분위수를 계산하지만 통계에서 멈추며 임계값을 적용하지 않고, 비교는 아직 존재하지 않는 detector에 미룹니다.

일단 기록된 실행 파일은 화면이 읽는 유일한 원본입니다. `RunSummary`와 `CheckResult.fromFile`이 디스크에서 다시 그리므로, 완료된 실행은 프로세스가 죽어도 살아남고 카메라를 켜지 않고도 다시 열어 볼 수 있습니다.

`cli/CommandStore.kt`, `cli/CommandCoordinator.kt`와 화면 어댑터 `LiveController`, `BenchmarkController`, `CtsController`. 한 CLI 요청의 상태 기계는 accepted → preparing → running → saving → succeeded 로 진행하며, 실패는 failed, 취소는 cancelling 을 거쳐 cancelled, 프로세스 재시작으로 끝나지 못한 요청은 interrupted 로 기록합니다. `CliStates.allows` 가 허용하는 전이만 `CommandStore.transition` 이 받습니다.

`submit` 은 기록을 먼저 저장한 뒤 main thread 에서 명령을 나눕니다. `cameras`, `probe`, `cts.cases` 는 화면 없이 coordinator 가 직접 완료하고(probe 는 IO 스레드에서 JSON·TXT 를 `files/cli/artifacts/<request_id>/` 에 씁니다), `preview`·`capture`·`benchmark.run`·`cts.run` 은 현재 붙어 있는 host(`screen` 이 live·benchmark·cts) 에 넘깁니다. benchmark.run 과 cts.run 은 Live 에서 `beginHandover` 뒤 다음 Activity 가 `continueHandover` 로 같은 요청을 이어받으며, 그 사이 `detach` 는 요청을 실패시키지 않습니다.

`complete` 는 saving 으로 옮긴 뒤 IO 스레드에서 artifact 의 크기와 SHA-256 을 계산하고 terminal state 를 정합니다. 취소 코드가 `EXECUTION_TIMEOUT` 인 경우 failed, 결과가 `cancelled` 이거나 실패가 `CANCELLED` 면 cancelled, 그 밖에는 succeeded 입니다. 이미 saving 에 들어간 요청은 취소해도 실제 결과로 끝나며 `cancel_effective` 로 늦은 취소를 표시합니다. `release` 는 active 요청과 timeout 을 정리하고, `CommandStore.cleanup` 은 만료·초과 기록을 지우면서 `onExpire` 로 그 요청의 artifact 디렉터리도 함께 지웁니다.

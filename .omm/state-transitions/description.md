BenchmarkRunner는 OPEN → CONFIGURE → FIRST_FRAME → CYCLE_CLOSE를 반복한 뒤 별도 세션에서 WARMUP → OBSERVE → STILL → RECORD → CLOSE를 수행합니다. 녹화 조건이 없으면 RECORD를 생략합니다. 녹화 사이클 실패만으로 실행 전체가 무효가 되지는 않습니다. 연속 실패 한도·관측 세션 실패·abort는 조기 종료 조건입니다.

카메라 수명주기, incident 창, validity와 회귀 판정은 별도 상태입니다. HistoryActivity는 목록·비교·삭제를 관리합니다. 비교 선택은 취소로 해제하고 화면 재생성 때 복원합니다.

콜백 그래프는 촬영·정지 조작을 유지하며 뒤로 가기로 숨깁니다. Lab은 close(done) 뒤에 열고 녹화·종료·CLI 작업 중에는 이동을 막습니다. Lab과 Probe는 카메라를 열지 않습니다. 관측·녹화 중에는 화면을 유지하며 비활성화 시 해제합니다. 일시정지한 Live와 실행하지 않는 CTS 프리뷰는 가림막으로 가립니다. 녹화 세션 종료는 MediaRecorder를 정지·저장하고 활성 카메라를 사진 프리뷰로 복원합니다. 화면 전환의 상세 조건은 ui-tool-handoff 관점에 있습니다.

API 전환은 기존 close 완료 후 새 엔진을 엽니다. 목록 열기와 모드 선택은 촬영하지 않습니다. 녹화 중에는 API·카메라·모드 변경을 막고 줌은 허용합니다. 카메라·API 변경은 EV·잠금·플래시와 제어 표시를 초기화합니다. 썸네일 조회는 onStart에서 시작하고 onStop에서 관찰·지연 갱신을 중단하며 이전 결과를 무효화합니다.

CLI는 accepted → preparing → running → saving → succeeded로 진행합니다. 실패·취소·중단, ID 중복과 충돌 처리는 하위 cli-request에서 설명합니다. 프로세스 재시작은 미완료 요청을 재실행하지 않습니다. 사진 저장 취소는 실제 저장과 경합할 수 있습니다.

Live 스트림 적용은 사진·녹화·저장·권한 요청·CLI 작업 중에 거절합니다. 기존 close(done)가 끝난 뒤 새 엔진에 설정을 전달하고 구성 성공값을 카메라·엔진별로 보관합니다. 실패하면 크기를 자동 대체하지 않으며 사용자가 직전 정상 구성으로 복구할 수 있습니다. Activity 재생성에서도 요청값과 정상 구성을 복원합니다.

App Bokeh는 JPEG 저장 후 편집하며 중복 촬영·CLI를 막습니다. worker는 오래된 결과를 버리고 실패해도 원본을 보존합니다. 중단 시 URI를 보관해 복귀 후 다시 편집합니다. 상세는 app-bokeh 요소에 있습니다.

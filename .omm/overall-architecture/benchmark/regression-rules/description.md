Regression thresholds are defined in `app/src/main/java/dev/halcamera/benchmark/RegressionRules.kt`. LATENCY rules trigger REGRESSED when relative change meets the percentage threshold AND absolute change meets the noise floor (ms), preventing false positives on small metrics. COUNT rules trigger on absolute change alone, as percentage is undefined for counts. The thresholds vary by metric: preview interval metrics (H.1, H.2) use 10% with a 2ms floor; launch/capture metrics use 15%; jitter (H.10) uses 20% with a 1ms floor; convergence metrics (H.6 to H.8) use 30% with a 200ms floor due to instability; counts (H.5, 2.7) require a change of 2, while callback failures (H.9) require a change of 1. The `init` block enforces that `deltaPct` is null only for COUNT rules. Any value change requires bumping the `VERSION`, currently set to `regression-rule-v1`. These thresholds are applied by a detector arriving in M4, while M1 fixes the table.

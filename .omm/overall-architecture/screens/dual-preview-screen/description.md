DualPreviewActivity는 기존 CLI 계약을 위한 Camera2·CameraX 물리 출력 화면입니다. Live의 Multi는 이 화면을 사용하지 않고 ConcurrentCameraActivity에서 장치를 각각 엽니다. Camera 1이 메인 프리뷰를 채우고 Camera 2는 그 위의 둥근 세로형 서브 프리뷰로 표시됩니다. 서브 프리뷰를 드래그하면 화면 범위 안에서 이동하며, 상대 위치를 저장하여 모드 전환과 다음 진입에서도 복원합니다. 접근성 동작으로 네 모서리로 이동할 수도 있습니다. CLI의 dual 명령은 Live의 close(done) 이후 이 화면을 열고, Photo 또는 Video를 선택하면 듀얼 장치를 닫은 뒤 해당 Live 모드로 돌아갑니다. Benchmark profile은 바꾸지 않습니다.

Photo와 같은 전체 화면 프리뷰, 상단 Camera2·펼침 버튼·Callback·Lab, Live 표시, 하단 측정값·갤러리·64dp 셔터·카메라 선택·모드·Save Events · ZIP 배치를 유지합니다. 별도의 Dual 제목과 화면을 나누는 패널은 없습니다. 상단 엔진 버튼으로 Camera2와 CameraX를 전환합니다. Live와 듀얼 모드 사이에서도 선택한 엔진을 유지합니다. Camera2의 Dual · P는 한 요청으로 두 센서 사진을 촬영합니다. Camera2에서는 메인 센서에 EV·AF/AE 잠금·터치 측광·수동 설정을 적용하고, CameraX에서는 사진과 메인 개별 제어를 비활성화합니다. 공통 줌은 두 엔진에서 지원하며, 하단 카메라 선택 버튼에서 Camera 1·2와 논리 ID를 선택합니다. 서브 영상의 ID 버튼으로 Camera 2를 바로 바꿀 수도 있습니다. 반대편에서 사용하는 ID는 후보에서 제외하며 카메라 선택 메뉴에서 메인과 서브를 교환합니다. 하단에는 일반 프리뷰와 같은 줌 버튼을 둡니다. 사진 촬영·녹화·종료 처리 중에는 모드·렌즈 변경을 받지 않습니다. Callback과 제어 메뉴를 펼치면 PiP가 버튼을 가리지 않도록 남은 공간에 맞춥니다. 기본 화면 문구는 영어이며, FPS·물리 ID와 촬영 상태만 표시합니다. 상태와 실패 시 다시 시작 버튼은 영상 위에 표시합니다. 물리 ID와 두 화면의 FPS는 기존 측정값 위치에 표시합니다. 크기 표시는 현재 엔진·물리 ID·출력 크기를 읽기 전용으로 보여 주는 Live Streams를 엽니다. Lab에서도 같은 구성을 표시하며 적용할 수 없는 단일 카메라 설정이나 Apply 버튼을 제공하지 않습니다. 프리뷰 준비 후 화면 켜짐을 유지하며 종료·실패 시 해제합니다. 측정값을 누르면 상세 정보에서 프레임 수·메타데이터 수·누락 수·SENSOR_TIMESTAMP·Sync 유형을 확인하고 보고서로 복사합니다. Callback은 논리 카메라의 Shutter·Metadata, 두 화면의 Main/Sub display, Camera2 사진의 Main/Sub photo 수신을 구분합니다. 화면 갱신 시각을 HAL 버퍼 도착 시각으로 표시하지 않습니다. 물리 ID와 센서 타임스탬프로 논리 요청에 연결하며 물리 센서 동기 그래프로 해석하지 않습니다. Save Events · ZIP은 기존 FlightRecorder와 IncidentExporter로 이전 10초·이후 5초 이벤트를 저장하며 픽셀은 저장하지 않습니다. physical timestamp는 별도의 dual_physical_result 이벤트로 저장합니다. FPS는 화면 갱신 횟수로 계산하며 두 물리 결과의 timestamp 차이는 센서 동기 보장을 뜻하지 않습니다. 실패 시 수치는 마지막 관측값으로 표시합니다.

DualPreviewPlanner는 후면 논리 멀티 카메라의 서로 다른 물리 카메라 두 개를 선택합니다. 기본 조합은 Wide+Tele, 다음은 Wide+UWide이며 둘 다 없으면 첫 두 카메라를 사용합니다. 공통 SurfaceTexture 크기 중 1080p 이하를 4:3, 16:9, 나머지 순서로 최대 네 개 시도합니다. API 28 미만, 논리 멀티 카메라 미지원, 물리 카메라 부족, 동일 렌즈, 공통 크기 없음은 거부 사유를 표시합니다.

DualPreviewSession은 공개 논리 ID를 열고 OutputConfiguration.setPhysicalCameraId로 각 출력을 연결합니다. API 29 이상에서는 isSessionConfigurationSupported를 확인하고, 거부되면 다음 크기를 시도합니다. 물리 ID를 직접 열 수 있다고 가정하지 않습니다. opening 중 종료 요청도 CameraDevice의 콜백과 onClosed를 기다립니다. 장치가 닫힌 뒤 SurfaceTexture를 해제하고 다음 세션을 시작합니다.

Camera2의 Dual · V는 각 physical camera의 프리뷰와 MediaRecorder surface를 같은 OutputConfiguration에서 공유합니다. 두 카메라의 MediaRecorder 출력 크기도 확인하며, 인코더 또는 HAL이 거부한 크기는 다음 후보로 넘어갑니다. 녹화 버튼을 누르면 H.264·30 fps 인코더 두 개를 시작하고 두 encoder surface를 repeating request에 추가합니다. 오디오는 저장하지 않으며 프리뷰 위치는 저장 영상에 영향을 주지 않습니다. 30 fps는 인코더 설정이고 실제 프레임 전달률을 보장하지 않습니다.

정지·화면 이탈 때 장치를 닫은 뒤 인코더를 종료하여 카메라별 MP4 두 개를 MediaLibrary로 저장합니다. 파일명은 공통 촬영 식별자와 A/B, physical camera ID를 포함합니다. 두 파일의 쓰기·공개 중 하나라도 실패하면 이번 저장의 MediaStore 항목을 모두 지웁니다. encoder 오류 또는 stop 실패도 두 파일을 공개하지 않습니다. 카메라·인코더를 순차 시작하므로 두 MP4의 시작 시각과 길이가 정확히 같다고 보장하지 않습니다.

CameraX는 같은 논리 카메라의 물리 ID 두 개를 ConcurrentCamera 설정으로 연결합니다. Dual · P는 공통 크기 중 첫 후보를 사용하고 Dual · V는 1280×720으로 구성합니다. 기기가 해당 구성을 거부하면 실패 상태를 표시하며 Camera2로 자동 전환하지 않습니다. 각 Preview는 GPU relay를 거쳐 화면과 해당 카메라의 H.264 인코더에 전달됩니다. 합성 영상이 아니며 MP4 두 개에 프리뷰 위치나 UI는 포함하지 않습니다. 장치의 onClosed와 CameraX surface 반환을 기다린 뒤 relay와 인코더 종료를 완료하고 다음 세션을 엽니다. CameraX provider는 듀얼 모드 전환마다 shutdown하지 않고 재사용합니다.

ConcurrentCameraActivity는 Live의 Multi · P와 Multi · V에서 여는 독립 장치 촬영 화면입니다. Photo·Video와 같은 상단 제어, 카메라별 크기 표시, 줌, 갤러리·64dp 셔터·카메라 선택, 네 모드와 Save Events · ZIP을 사용합니다. Photo·Video의 PIP 위치에는 Split 버튼을 배치하며 Manual 버튼과 입력창은 제공하지 않습니다. MultiSession 계약으로 Camera2 ConcurrentSession과 CameraXMultiSession을 선택합니다. CameraX는 광고한 동시 조합의 최대 두 장치를 지원하며 Preview와 ImageCapture를 바인딩합니다.

Split 설정창과 끌어 맞추기 배치 규칙은 split-layout 요소가 설명합니다. 이 화면은 그 결과인 배치와 패널 순서를 받아 패널 크기를 정하고, 같은 장치 조합 안의 순서·배치 변경은 세션을 유지한 채 패널만 옮깁니다.

각 패널은 위에서부터 이름표 바, 프리뷰, 측정 행 순서로 놓고 패널 아래쪽에 붙입니다. 9:16 프리뷰가 패널보다 짧을 때 남는 높이가 셔터 옆 검정 띠가 아니라 이름표 위의 배경으로 가도록 하기 위해서입니다. 프리뷰 TextureView는 스트림 비율에 맞춘 크기로 두어 GL 레터박스가 생기지 않게 합니다. 이름표 바는 28dp로 보이고, 48dp 터치 영역은 프리뷰를 덮지 않도록 바 위쪽 빈 공간으로 늘립니다. Multi는 하단 공용 측정 행을 쓰지 않고 카메라마다 자기 결과의 FPS와 EXP만 표시합니다. 좌우·격자 배치에서는 폭이 좁으므로 프리뷰 바로 아래 24dp 행에, 위아래 배치에서는 이름표 바 오른쪽에 표시합니다. 측정값은 패널의 자식이므로 끌기와 배치 변경에 함께 움직입니다. 1.5초 안에 결과가 없는 카메라는 값 대신 —를 표시합니다. Callback 그래프를 여는 동안에는 이 측정값을 모두 숨기고 프리뷰가 그 자리를 씁니다.

상단 크기 표시는 모든 카메라를 이름표와 같은 화면 번호로 나열합니다. 카메라 수와 관계없이 `1 · P 1280×720   J 1920×1440`처럼 카메라마다 한 줄씩 표시하고, 선택한 카메라의 줄을 밝게 강조합니다. 크기 표시를 누르면 MultiSizeSheet가 위에서 내려와 화면 순서대로 카메라마다 Preview와 JPEG 크기를 고르게 합니다. 선택지는 ConcurrentPlanner.previewChoices·photoChoices가 동시 세션이 보장하는 s720p(1280×720 이하)와 s1440p(1920×1440 이하) 안의 크기만 큰 순서로 제공하며, 기본값은 그중 가장 큰 크기입니다. 보장 밖 크기는 실제 세션 검사에서 거부될 수 있으므로 제공하지 않습니다. Apply한 크기가 지금과 다르면 close(done) 뒤 세션을 다시 구성하고, withSizes는 선택지에 없는 값을 무시할 뿐 다른 크기로 바꾸지 않습니다. 영상은 프리뷰 크기를 그대로 씁니다. 선택한 크기는 카메라 ID별로 기억하므로 장치 조합을 바꿨다가 돌아와도 유지되며 Activity를 다시 만들 때 복원합니다.

장치 이름에는 드래그 표시를 두며 선택한 장치는 흰 테두리와 체크로 구분합니다. 장치 이름을 누르면 해당 장치의 줌·AF·AE·EV 제어로 전환합니다. 프리뷰 터치는 해당 장치의 초점·노출 측광과 핀치 줌을 처리합니다. Callback 그래프는 자체 ID 버튼 없이 이름표로 선택한 장치의 실제 HAL 출력만 표시하며 GPU 인코더를 HAL 녹화 스트림으로 표시하지 않습니다. 같은 세션 안에서 장치를 전환해도 각 장치의 요청값을 보존합니다. Multi는 Manual과 AEB를 제공하지 않으며 플래시는 Off·Torch를 사용합니다. ConcurrentSession은 ManualControls와 bracket을 제거한 요청을 적용합니다. Telemetry는 장치별 세션 키에 카메라 결과와 프리뷰·JPEG 이벤트를 기록하며 이벤트 ZIP에는 이미지 픽셀을 넣지 않습니다.

ConcurrentLifecycle은 장치별 open·streaming·closing·closed 상태를 관리합니다. 모든 장치를 연 뒤 세션을 구성하고 모든 출력의 실제 프레임 도착 이후 셔터를 활성화합니다. Gallery·Lab 복귀 시 TextureView 크기가 확정된 뒤 시작을 다시 시도합니다. 출력 구성이 거부되면 실패와 Retry를 표시합니다. 종료 중 늦게 도착하는 open 콜백과 모든 onClosed를 기다린 뒤 compositor를 해제하고 ConcurrentLease를 넘깁니다. Live는 자신의 close(done) 이후 이 화면을 열고 돌아오면 원래 엔진의 프리뷰를 복구합니다. Benchmark 경로와 프로파일은 바꾸지 않습니다.

Camera2 사진은 각 장치의 Image.timestamp와 CaptureResult.SENSOR_TIMESTAMP를 연결한 JPEG이며, CameraX 사진은 ImageCapture가 전달한 원본 JPEG와 이미지 시각을 저장합니다. Multi는 Physical·Service PIP를 합성하지 않습니다. ConcurrentPhotoStore는 공통 group ID, 장치 ID, 크기, 시각 기준과 성공·실패를 JSON에 기록합니다. 녹화 중에는 카메라 선택 아이콘 대신 사진 아이콘을 표시해 장치별 원본 JPEG를 저장하며 두 영상은 계속 녹화합니다. 사진 제한 시간은 10초이며 만료 시 미완료 장치를 실패로 기록합니다. Camera2는 장치를 닫고, CameraX는 진행 중인 사진 묶음을 종료합니다. 부분 실패는 성공한 파일을 유지하며 JSON 저장 실패는 해당 사진 묶음을 롤백합니다.

영상은 장치별 독립 MP4를 저장합니다. 마이크 권한을 받은 뒤 MultiAudio가 하나의 MIC를 녹음하고 MultiRecording이 같은 AAC를 각 영상에 결합합니다. 무음 대체는 하지 않으며 결합에 실패하면 해당 묶음을 회수합니다. 인코더 크기는 해당 장치의 프리뷰 스트림과 센서 회전에서 정하며 Split 패널 크기와 무관합니다. preserveFullFrame은 EGL 대상 크기에 전체 입력을 맞추어 표시하며 화면 배치를 영상 크롭으로 사용하지 않습니다. 화면 전체·다른 장치·UI를 저장 영상에 합성하지 않습니다. 종료 시 진행 중인 녹화의 저장을 마친 뒤 자원을 해제하며, 저장 오류는 성공으로 보고하지 않습니다. 사진·영상의 센서 동기는 보장하지 않습니다.

Multi V는 MicrophoneCapture가 AudioRecord의 MONOTONIC timestamp와 PCM 프레임 위치를 확보한 후 시작합니다. MultiRecording은 모든 영상 입력의 종료 콜백을 모은 뒤 오디오를 별도 IO 스레드에서 종료합니다. TimestampedVideoRecording이 실제 인코딩된 첫 프레임 시각을 보존하고 RecordingTimeline이 같은 마이크 AAC를 각 영상의 시간축으로 잘라 결합합니다. 하드웨어 시각을 얻지 못하면 무음으로 대체하지 않고 실패로 보고하며, AAC 프레임 경계와 기기 처리 지연에 따른 잔여 오차는 보장하지 않습니다.

상단 Split은 LiveChoiceSheet.Edge.TOP으로 위에서, 하단 카메라 버튼은 Edge.BOTTOM으로 아래에서 같은 설정창을 엽니다. 한 창에서 촬영할 카메라 수, 독립 CameraDevice 조합과 화면 순서를 정하며 배치 선택 항목은 두지 않습니다. Apply 전까지는 초안이며 닫기와 뒤로 가기는 변경을 버립니다. 카메라 수는 기기가 광고한 동시 조합의 크기에서 선택하며, 가능한 수가 하나면 읽기 전용으로 표시합니다. 광고되지 않은 조합은 Unavailable combinations를 펼치면 보이며 비활성화 상태를 유지합니다. 실제 세션 지원 검사도 적용 전에 수행합니다. 설정창의 Screen 순서는 현재 화면 배치 순서이며, 같은 장치 조합의 순서만 바꾸면 패널만 옮기고 세션을 유지합니다. 장치 조합이나 촬영 모드를 바꾸면 close(done) 뒤 재구성합니다.

배치는 Windows의 창 끌어 맞추기처럼 정합니다. 기본은 좌우 배치입니다. 패널 위쪽 이름표를 250ms 누르면 끌기가 시작되며, 시스템 길게 누르기 시간보다 짧게 두어 바로 집히도록 합니다. 프리뷰를 길게 누르는 AE·AF 고정과는 겹치지 않습니다. 집는 순간 흰 테두리로 현재 자리를 보여 주고, 끄는 동안 패널이 손가락을 따라오며 테두리가 놓일 자리를 미리 보여 줍니다. 판정은 손가락 위치가 아니라 끌고 있는 패널의 중심으로 합니다. 이름표가 패널 위쪽에 있어서 손가락으로 판정하면 집는 순간 위쪽 가장자리로 읽히기 때문입니다. 패널 중심이 미리보기 영역의 가장자리 22% 안에 들어가면 왼쪽·오른쪽은 좌우 배치, 위·아래는 위아래 배치로 바꾸고 끈 패널을 그쪽 칸에 넣습니다. 3개 이상이면 모서리는 격자 칸을 고르며, 2개일 때 모서리는 더 가까운 가장자리를 따릅니다. 가운데에 놓으면 아래 패널과 자리를 바꾸고 배치는 유지합니다. 화면 낭독기용으로 이름표에 Move to left·right·top·bottom 접근성 동작을 둡니다. 배치 변경은 프리뷰 크기만 바꾸므로 세션을 유지하며, 녹화·촬영·종료 중에는 끌기를 시작하지 않습니다. 배치와 순서는 화면 회전 등으로 Activity를 다시 만들 때 복원합니다.

SplitChoiceSheet는 설정창을 그리며 SplitSelection은 지원 조합·장치 수·화면별 교환 규칙을 순수 Kotlin으로 관리합니다. SplitArrangement는 배치와 패널 순서, 놓은 위치에서 다음 배치를 계산하는 규칙을 Android 의존성 없이 담고 JVM 테스트로 검증합니다. SplitPanelDrag는 누르기 타이머, 패널 이동, 미리보기 테두리, 접근성 동작만 처리합니다. 초안은 적용 전까지 현재 세션 설정을 바꾸지 않습니다. 화면과 설정창의 버튼 모양은 CameraWidgets.chromeButton을 재사용합니다.

카메라 수·화면 순서·Sizes의 크기 선택 버튼은 CameraWidgets.choiceButton을 공유합니다. 이 함수는 선택창과 현재 값·접근성 설명만 갱신하며 초안 변경은 콜백으로 전달합니다. 설정창의 Apply와 닫기는 각 초안의 적용 여부를 결정합니다.

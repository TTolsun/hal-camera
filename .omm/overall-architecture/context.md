이 앱은 일반 사용자용 유틸리티가 아니라 카메라 작업을 위한 계측 도구입니다. 읽는 사람은 같은 단말에서 카메라 빌드끼리 비교하는 개발자이기 때문에, 설계 전반이 "무엇이 잘못되었는지 알려 준다"보다 "무엇을 어떤 조건에서 관측했는지 말한다"를 일관되게 우선합니다.

이런 성향이 언뜻 이상해 보이는 선택 세 가지를 설명해 줍니다. 첫째, 모든 타임스탬프는 `SystemClock.elapsedRealtimeNanos()`이고 JSON에는 십진수 문자열로 기록되는데, 이는 JavaScript 도구에서 나노초 정밀도가 반올림되지 않도록 하기 위해서입니다. 둘째, 모든 export 결과물이 측정하지 않은 항목을 산문으로 명시합니다(HAL 실행 시간, 화면에 그려진 프리뷰 드롭, 근본 원인). 셋째, 코드에 의존성 주입 프레임워크도 Compose도 Room도 코루틴도 없습니다. 뷰는 Kotlin으로 직접 생성하고, 스레딩은 `Handler`와 단일 스레드 executor로 처리하며, JSON은 `org.json`을 파일 경계의 코덱 안에만 가둬 두어 계약 전체가 순수 JVM에서 테스트되도록 했습니다.

기준 문서는 `docs/`에 있습니다. `PRODUCT-v0.2.md`가 건강 판정 제품을, `PLAN-BenchMarker-v0.3.md`가 벤치마크 전환을, `METRICS.md`가 각 지표 ID(1.x, 2.x, 3.x, H.x)의 계산 방법을 정의합니다. 소스 주석이 이 문서들의 장·절 번호를 직접 인용하고 있으므로, 동작을 바꾸려면 문서를 먼저 고치는 것이 이 프로젝트의 전제입니다.
